# 第一部分　图像模态全栈技术体系

## 1. 分层模型：先建立坐标系

| 层 | 名称 | 核心问题 | 输入→输出 | 典型技术 |
|---|---|---|---|---|
| L0 | 成像与采集 | 光如何变成信号 | 场景 → 传感器电信号 | 光学、曝光、Bayer 阵列、去马赛克、ISP |
| L1 | 数字表示 | 如何离散化与描述 | 信号 → 像素矩阵 + 元数据 | 采样、量化、色彩空间、编码格式 |
| L2 | 底层处理 | 如何改善像素本身 | 图像 → 图像 | 几何、色彩、滤波、复原 |
| L3 | 中层表征 | 如何抽取可用的"证据" | 图像 → 特征/区域 | 特征点、超像素、边缘、光流 |
| L4 | 高层语义 | 图像里"是什么、在哪" | 图像 → 标签/框/掩码/文本 | 分类、检测、分割、关键点、OCR |
| L5 | 生成与编码 | 如何造图、存图、找图 | 条件 → 图像；图像 → 码流/向量 | 扩散、GAN、编解码、检索 |
| L6 | 系统工程 | 如何规模化运转 | 数据+模型 → 可复现产物 | 流水线、训练、部署、治理 |

关键判断：**L2 的算子决定"能用"，L4 的模型决定"有用"，L6 的工程决定"好用"**。绝大多数图像工具死在 L6，而不是算法不够强。

## 2. 图像基础属性（L0–L1）

### 2.1 数字表示：像素、位深、通道

**（1）采样与量化**

- 采样（sampling）：连续光强分布 → 规则网格。采样率不足会产生**混叠（aliasing）**，典型表现是摩尔纹、锯齿、细密纹理跳变。工程对策是缩放前先低通（面积平均/高斯），即"抗锯齿"。
- 量化（quantization）：连续幅值 → 离散电平。量化步长决定**色带（banding）**风险，8 bit 在平滑渐变上最易出现。
- 像素不是"点"，是**面积元的积分近似**。因此下采样必须做面积平均，直接抽取会丢能量、产生闪烁。

**（2）位深**

| 位深 | 电平数 | 典型载体 | 说明 |
|---|---|---|---|
| 1 bit | 2 | 二值图、掩码 | 标注掩码、形态学中间结果 |
| 8 bit/通道 | 256 | JPEG/PNG/WebP | 消费级标准；24 bit/像素（RGB） |
| 10/12 bit | 1024/4096 | HDR 视频、RAW、医学 | 减少色带，需硬件/格式支持 |
| 16 bit/通道 | 65536 | TIFF、PNG、遥感、显微 | 科学成像主力，动态范围大 |
| 32 bit float | — | EXR、HDR、渲染中间图 | 可表示 >1 的高光，线性空间计算 |

**易错点**：位深是"每通道"还是"每像素"必须显式标注；8 bit RGB 叫 24 位色，不叫 8 位色。

**（3）通道与内存布局**

- 常见通道组合：`Gray`、`RGB`、`BGR`（OpenCV 默认）、`RGBA`、`CMYK`（印刷，设备相关）、`HSV/HSL`、`Lab`、`YCbCr`、`YUV`、`XYZ`。
- Alpha：直通（straight）与预乘（premultiplied）两种语义。合成公式不同，混用会导致半透明边缘发黑或发白。**缩放/滤波必须在预乘空间做**，否则透明边缘会渗出背景色。
- 张量布局：`HWC`（图像库）、`CHW`（PyTorch）、`NHWC`（TensorFlow/TFLite）。转换是高频 bug 来源。
- 值域：`[0,255] uint8`、`[0,1] float`、`[-1,1]`、ImageNet 均值方差归一化。**同一算子在不同值域下结果不同**，工作台必须把值域作为显式契约。

**（4）图像类型谱系**

| 类型 | 特征 | 特殊处理 |
|---|---|---|
| 位图 / 矢量 | 像素阵列 / 几何图元 | 矢量化（potrace）、SVG 光栅化 |
| 二值 / 灰度 / 彩色 | 通道数与语义 | 灰度化权重（BT.601/709） |
| 多光谱 / 高光谱 | 数十至数百波段 | 波段组合、伪彩、降维 |
| 深度图 / 视差图 | 单通道距离 | 无效值掩码、点云反投影 |
| 医学影像 | DICOM、HU 值、窗宽窗位 | 12/16 bit、方向标签、匿名化 |
| 遥感影像 | 超大尺寸、地理坐标、16 bit | 瓦片金字塔、投影、切片 |
| 全景 / 球面 | 等距柱状投影 | 球面重投影、接缝 |
| 序列 / 视频 | 时间维度 | 帧抽取、跟踪、时序一致性 |

### 2.2 色彩空间与转换规则

**（1）三大类色彩空间**

| 类别 | 代表 | 特点 | 适用 |
|---|---|---|---|
| 设备相关 RGB | sRGB、Adobe RGB、Display P3、Rec.2020 | 三原色+传递函数定义，需 ICC 才唯一 | 采集、显示、存储 |
| 感知/均匀 | Lab、Luv、OKLab | 近似感知均匀，ΔE 可比 | 色彩差异、色彩迁移、调色 |
| 分量/传输 | YCbCr、YUV、HSV、HSL | 亮度色度分离，便于压缩/交互 | 视频编码、抠像、调色 UI |
| 设备相关 CMYK | CMYK | 依赖纸张与油墨 | 印刷输出 |

**（2）转换的正确路径**

- 任意 RGB 空间之间**不能直接换矩阵**：必须 `RGB → 线性化 → XYZ(D50 PCS) → 目标线性 RGB → 编码`，其中包含**传递函数（EOTF/OETF）**与**色适应（Bradford）**。
- sRGB 传递函数是分段函数：`c ≤ 0.04045` 时 `c/12.92`，否则 `((c+0.055)/1.055)^2.4`。近似 γ≈2.2 只用于粗算。
- 亮度权重随标准变化：BT.601 `0.299/0.587/0.114`，BT.709 `0.2126/0.7152/0.0722`，BT.2020 `0.2627/0.6780/0.0593`。**用错标准会导致灰度图偏色**，这是最常见的隐蔽 bug。
- RGB↔HSV/HSL 是纯几何变换（无色彩管理含义），**只在 UI 交互层使用，不能用于存储与计算**。
- Lab 转换依赖白点（D65/D50），Γ 值不同结果不可比；ΔE76 / ΔE94 / ΔE2000 精度递增，工业验色用 ΔE2000。

**（3）必须遵守的三条工程规则**

1. **线性空间做运算**：模糊、缩放、平均、混合、光照计算都应先把编码值线性化。在 sRGB 上直接平均会让暗部偏亮、边缘发灰。
2. **运算后回到显示空间**：输出前重新编码，否则画面"发灰发暗"。
3. **色彩配置必须随文件走**：缺 ICC 时按 sRGB 兜底并显式标注"假设 sRGB"，不要静默处理。

**（4）色彩管理链路**

`相机 RAW → 白平衡增益 → 去马赛克 → 相机矩阵 → 场景线性 → 色调映射 → 输出空间编码 → 嵌入 ICC`

工作台至少要做到：读取 ICC、按 ICC 转换、软打样（模拟印刷/目标设备）、转换时保留或剥离配置的显式选择。

### 2.3 常见图像格式特性

| 格式 | 压缩 | 位深 | Alpha | 动画 | HDR/广色域 | 典型用途 | 主要局限 |
|---|---|---|---|---|---|---|---|
| BMP | 无/简单 RLE | 1–32 | 有 | 否 | 否 | 兼容性兜底 | 体积大 |
| PNG | 无损（DEFLATE+预测滤波） | 1–16 | 有 | APNG | 弱 | 截图、掩码、线条图 | 照片体积大、解码慢 |
| JPEG | 有损（8×8 DCT+量化+熵编码） | 8 | 无 | 否 | 否 | 照片分发 | 块效应、振铃、无透明 |
| WebP | 有损/无损 | 8 | 有 | 有 | 弱 | Web 通用 | 生态兼容性一般 |
| AVIF | 有损/无损（AV1 帧内） | 8–12 | 有 | 有 | 是 | 高质量 Web、HDR | 编码慢、旧端不支持 |
| JPEG XL | 有损/无损，可无损转码 JPEG | 8–32 | 有 | 有 | 是 | 归档、渐进加载 | 生态尚在铺开 |
| HEIC/HEIF | 有损（HEVC 帧内） | 8–16 | 有 | 有 | 是 | 移动端相册 | 专利与兼容性 |
| TIFF | 无/多种 | 1–32 | 有 | 多页 | 是 | 印刷、医学、科学 | 体积大、方言多 |
| GIF | 无损 LZW | 8（调色板） | 二值 | 有 | 否 | 表情包、简单动图 | 256 色、锯齿 |
| SVG | 矢量 | — | 有 | 有 | 是 | 图标、图表、论文插图 | 光栅化依赖渲染器 |
| EXR | 无损/有损（PIZ/ZIP/DWAA） | 16/32 float | 有 | 多通道 | 是 | 影视合成、渲染 | 体积大、需专用库 |
| DICOM | 无损/有损 | 8–16 | 无 | 多帧 | 是 | 医学影像 | 需专业解析与匿名化 |
| PSD | 分层未压缩/RLE | 8–32 | 有 | 否 | 是 | 设计源文件 | 解析复杂、图层语义 |

**格式选择决策树**（工作台内置推荐逻辑）：

1. 需要透明/线条/文字 → PNG 或 WebP 无损；需要无限缩放 → SVG。
2. 照片且要小 → AVIF > WebP > JPEG（按兼容性回退）。
3. 中间处理与科研存档 → PNG-16 或 TIFF；HDR/合成 → EXR。
4. 需要保留图层/可再编辑 → PSD/分层 TIFF，并同时导出扁平副本。

**元数据是格式的一部分**：EXIF（相机、曝光、**Orientation 方向标志**）、GPS、IPTC（版权/说明）、XMP（可编辑扩展）、ICC（色彩配置）、C2PA（内容凭证）。方向标志必须"读取即应用"，否则会出现"导入后图片躺倒"的经典缺陷。

### 2.4 图像质量评价标准

**（1）全参考（有原图）**

| 指标 | 原理 | 优点 | 盲区 |
|---|---|---|---|
| MSE / PSNR | 逐像素误差，`PSNR=10·log10(MAX²/MSE)` | 快、可解释 | 与主观感知弱相关，偏好模糊 |
| SSIM / MS-SSIM | 亮度·对比度·结构三项比较，多尺度加权 | 与感知较一致 | 对位移/缩放敏感，纹理区域偏差 |
| LPIPS | 深度特征空间距离（VGG/Alex） | 最接近人眼 | 依赖网络，跨数据集不可比 |
| FSIM / VIF | 相位一致性 / 信息保真度 | 对结构退化敏感 | 计算成本高 |

**（2）无参考（只有退化图）**

- 传统：BRISQUE、NIQE、PIQE（自然场景统计先验）。
- 深度：MUSIQ、MANIQA、CLIP-IQA（多尺度/多模态）。
- 注意：无参考指标跨域泛化差，**只能用于同域排序，不能当绝对分**。

**（3）任务相关指标**

| 任务 | 指标 |
|---|---|
| 分类 | Top-1/Top-5 Acc、mAP（多标签）、F1、AUC |
| 检测 | AP@0.5、AP@[.5:.95]、AR、按尺度（S/M/L）分组、误检率 |
| 分割 | mIoU、Dice、Boundary IoU、实例 AP、全景 PQ |
| 关键点 | OKS-based AP、PCK、NME |
| OCR | 检测 Hmean、识别准确率/CER、端到端 F1 |
| 生成 | FID、KID、CLIPScore、ImageReward、人类偏好胜率 |
| 压缩 | BD-rate、码率-质量曲线 |
| 检索 | Recall@K、mAP、NDCG |

**（4）主观评价与工程口径**

- MOS（5 级/9 级）、双刺激连续质量标度、成对比较（BT-500 模型）。人工评测是唯一"真值"，自动指标只做代理。
- 工作台应把"指标定义+数据集版本+模型版本"三者绑定成**评测报告**，否则数字不可比。FID 对样本量敏感（建议 ≥10k），小样本结论不可信。

## 3. 底层图像处理能力（L2）：全量算子与典型算法

统一说明：所有几何类算子最终都归约为 **重映射（remap）**——给定输出坐标到输入坐标的映射表 + 插值核；所有滤波类算子都是 **卷积/邻域聚合**的特例。抓住这两条，算子数量就从"几百个"降到"两类"。

### 3.1 几何变换

| 算子 | 数学形式 | 典型算法/实现 | 关键参数 | 失效场景 |
|---|---|---|---|---|
| 缩放 resize | 坐标缩放 + 重采样 | 最近邻、双线性、双三次、Lanczos、面积平均（下采样）、Mipmap | 目标尺寸/缩放因子、插值核、是否保持宽高比 | 放大用最近邻→锯齿；缩小不预滤波→混叠 |
| 裁剪 crop | ROI 截取 | 坐标裁剪、中心/智能裁剪（显著性/人脸）、内容感知 | ROI、填充模式 | 越界、坐标系（左上/中心）不一致 |
| 填充 pad | 边界外延 | constant / replicate / reflect / wrap / 镜像 | 尺寸、值 | 反射填充在 1px 边界退化 |
| 旋转 rotate | 旋转矩阵 | 绕中心/任意点、扩展画布、插值 | 角度、插值、画布策略 | 90° 倍数应走转置而非插值（无损） |
| 翻转 flip | 镜像 | 水平/垂直/对角 | — | 标注框需同步翻转 |
| 仿射 affine | 6 自由度（平移/旋转/缩放/错切） | `cv2.warpAffine`、三点定标 | 3 点对应、插值 | 无法表达透视 |
| 透视 perspective | 8 自由度单应 H | `cv2.warpPerspective`、四点定标、DLT | 4 点对应、单应矩阵 | 超出发散区域、极端角度畸变 |
| 畸变校正 | 径向+切向多项式（Brown-Conrady） | `k1,k2,k3`（径向）、`p1,p2`（切向）、鱼眼模型、去畸变查找表 | 内参 K、畸变系数 | 系数符号/归一化坐标搞错→"更歪" |
| 相机标定 | 张正友标定 | 棋盘格/圆点靶标、多视图优化 | 靶标规格、视图数 | 视图共面→内参不可解 |
| 极坐标/展开 | 坐标非线性变换 | 极坐标变换、柱面/球面展开、鱼眼展开 | 中心、半径、插值 | 采样密度不均 |
| 拼接 panorama | 匹配+单应+融合 | 特征匹配+RANSAC、曝光补偿、多频段融合（Laplacian pyramid） | 匹配阈值、投影模型 | 视差导致重影、运动物体 |
| 内容感知缩放 | 能量最小化 | Seam Carving（梯度能量+动态规划）、接缝插入/删除 | 目标尺寸、保护掩码 | 强结构/人脸变形 |
| 网格变形 | 控制点插值 | 薄板样条 TPS、自由变形 FFD、液化 | 控制点、刚度 | 折叠、自交 |

**工程要点**

- 插值核选择：**缩小用面积平均/Lanczos3，放大用双三次/Lanczos3**，实时预览用双线性；医学/科学测量禁用任何锐化型插值。
- 坐标约定：像素中心在整数坐标还是半整数（`align_corners`），跨库（OpenCV/PyTorch/PIL）不一致会造成 0.5px 偏移，累积到多尺度就明显。
- 几何变换必须与**标注同步**：框、多边形、关键点、掩码各自有不同的变换规则（框变换后要重新求外接矩形，掩码要最近邻重采样，关键点只做坐标映射）。
- 单应分解可估相机姿态（R/t），是文档矫正、AR、测量类功能的基础。

### 3.2 色彩处理

| 算子 | 说明 | 典型算法 | 关键参数 |
|---|---|---|---|
| 空间转换 | RGB/HSV/Lab/YCbCr/CMYK | 矩阵+传递函数+ICC（LittleCMS） | 源/目标配置、渲染意图 |
| 亮度/曝光 | 整体增益（线性空间乘性） | 线性缩放、EV 补偿 | EV 值、是否线性空间 |
| 对比度 | 围绕中灰拉伸 | 线性拉伸、S 曲线（sigmoid/贝塞尔）、曲线编辑器 | 强度、支点 |
| 伽马 | 幂律调整 | `out = in^(1/γ)` | γ（0.4–2.5） |
| 色阶/黑白场 | 重映射区间 | 输入黑/白点、输出黑/白点 | 三点 |
| 饱和度 | 色度缩放 | HSL 的 S 通道、Lab 的 a/b 缩放、自然饱和度（按已饱和程度衰减） | 强度、肤色保护 |
| 色相 | 角度旋转 | HSV 的 H 通道、色相环偏移 | 角度、范围 |
| 白平衡 | 消色偏 | 灰世界、白点（最亮像素）、色温/色调（Tint）、RAW 通道增益、AWB 网络 | 色温 K、色调 |
| 色彩校正 | 建立输入→参考映射 | 3×3 矩阵、多项式回归、**3D LUT（.cube）**、薄板样条 | LUT 大小、拟合方式 |
| 色彩迁移 | 统计量/风格对齐 | Reinhard（Lab 均值方差）、AdaIN、直方图匹配 | 强度、参考图 |
| 色调映射 | HDR→SDR | Reinhard、Drago、ACES Filmic、局部算子（双边/引导滤波分层） | 曝光、对比、饱和 |
| 色彩分级 | 阴影/中间调/高光分离调色 | Lift/Gamma/Gain、色轮、三向曲线 | 三区参数 |
| 通道操作 | 分离/合并/交换/提取 | 通道拆分、通道运算（加减乘除、阈值） | 通道选择 |
| 伪彩 | 灰度→彩色映射 | 查找表（Jet/Viridis/Turbo）、自定义色带 | 色带、范围 |
| 色彩量化 | 减少颜色数 | K-means、中位切分、八叉树、抖动（Floyd-Steinberg） | 颜色数、抖动强度 |

**必须内置的"正确性护栏"**：调亮度/模糊/混合时提示"当前在非线性空间"，并提供一键线性化；导出时检测 ICC 缺失与广色域越界（超色域像素裁切警告）。

### 3.3 滤波增强

| 类别 | 算子 | 典型算法 | 适用 | 副作用 |
|---|---|---|---|---|
| 线性平滑 | 均值/高斯/盒式 | 可分离卷积、积分图（O(1) 盒滤波） | 通用降噪、预处理 | 糊边 |
| 保边平滑 | 双边、导向滤波、域变换 | 双边（空间×值域核）、导向滤波（线性模型）、WLS | 磨皮、HDR 分层、抠图 | 双边慢，易产生梯度反转 |
| 中值类 | 中值、自适应中值 | 排序统计、直方图加速 | 椒盐噪声 | 细结构丢失 |
| 非局部 | NLM、BM3D | 相似块加权、块匹配+3D变换协同滤波 | 高斯噪声、真实噪声 | 慢、纹理过度平滑 |
| 扩散 | 各向异性扩散、PM 方程 | 梯度自适应扩散系数 | 保边去噪 | 迭代次数敏感 |
| 形态学 | 腐蚀/膨胀/开/闭/顶帽/黑帽/击中击不中/骨架 | 结构元滑动、距离变换 | 掩码清理、粘连分离、缺陷检测 | 结构元尺寸决定一切 |
| 锐化 | USM、拉普拉斯、高通叠加 | 反锐化掩模、频域提升 | 提升观感 | 光晕、噪声放大 |
| 边缘检测 | Sobel/Prewitt/Scharr、Laplacian/LoG、Canny、结构化边缘 | 梯度算子、零交叉、NMS+双阈值+滞后 | 轮廓、测量、控制图 | 阈值敏感 |
| 直方图 | 均衡、CLAHE、规定化（匹配） | 累积分布映射、分块+clip limit+双线性插值 | 低对比、医学/遥感 | 噪声放大、色偏（应在 Lab 的 L 上做） |
| 光照增强 | Retinex、同态滤波、自适应伽马、低光增强网络 | `I = R·L` 分解、MSRCR、Zero-DCE、Retinexformer | 逆光、夜间、水下 | 光晕、颜色失真 |
| 频域 | DFT/DCT、低通/高通/带阻/陷波 | FFT 乘法滤波、理想/巴特沃斯/高斯响应 | 去周期噪声、去网纹 | 振铃 |
| 小波 | 小波阈值去噪、融合 | 多尺度分解+软阈值 | 混合噪声、融合 | 阈值选择 |
| 超像素 | SLIC、Felzenszwalb、分水岭 | K-means 聚类（颜色+空间）、图割、浸没模拟 | 分割预处理、标注加速 | 边界不贴合 |
| 连通域 | 标记、属性统计、孔洞填充 | 两遍扫描、并查集、轮廓层级（Suzuki） | 计数、测量、后处理 | 8/4 邻接差异 |

**参数化建议**：每个算子必须暴露"物理可解释参数"（半径以像素、强度以百分比、色温以 K），而不是裸的权重数组；同时提供"自动参数"（基于噪声估计、直方图统计、曝光评估），这是把专业工具做成大众工具的关键。

### 3.4 复原重建

统一退化模型：`y = (x ⊛ k) ↓s + n`（模糊核 k、下采样 s、噪声 n），复原就是反演它。**盲复原**（未知 k）比**非盲**难一个量级，也是深度学习的优势区。

| 任务 | 退化 | 传统方法 | 深度方法 | 评价 |
|---|---|---|---|---|
| 去噪 | 高斯/泊松/真实传感器噪声 | 高斯/双边/NLM/BM3D | DnCNN、FFDNet、SwinIR、真实噪声建模（Noise2Noise、自监督） | PSNR/SSIM/LPIPS + 纹理保真 |
| 去模糊 | 运动/散焦/混合 | 维纳滤波、Richardson-Lucy、盲反卷积 | DeblurGAN-v2、NAFNet、Restormer、事件相机辅助 | 振铃与伪影 |
| 去雾 | 大气散射 `I = J·t + A(1-t)` | 暗通道先验 DCP、颜色衰减先验、CLAHE | AOD-Net、GridDehaze、DehazeFormer | 色彩自然度、深度边缘 |
| 去雨/去雪 | 雨线、雨滴、雪花 | 频域滤波、层分离 | DerainNet、MPRNet、半监督真实雨 | 背景细节保留 |
| 去反光/去阴影 | 反射层、照明层 | 独立成分、梯度域 | 层分离网络 | 材质真实感 |
| 去摩尔纹/去网纹 | 周期干扰 | 陷波滤波、频域 | UHDM、Moiré GAN | 纹理不丢失 |
| 超分辨率 | 低分辨率 | 双三次/Lanczos、稀疏编码 | SRCNN→EDSR/RCAN→ESRGAN（感知）→Real-ESRGAN（盲）→LIIF（任意尺度） | PSNR vs LPIPS 权衡 |
| 修复补全 | 缺失区域 | PatchMatch、纹理合成、扩散填充 | LaMa、MAT、SD Inpaint、全局一致扩散 | 结构连续性与语义合理 |
| 老照片修复 | 划痕+噪点+褪色+缺失 | 手工+中值 | 划痕检测网络、人脸先验（GFPGAN）、上色 | 人脸保真 |
| 上色 | 灰度→彩色 | 用户 scribble 传播、色彩迁移 | DeOldify、InstColorization、扩散上色 | 语义合理、可交互 |
| 图像翻译 | 域间映射 | 直方图/LUT | pix2pix、CycleGAN、CUT、扩散编辑 | 结构保持 |

**取舍原则**：PSNR 最优的模型往往"糊但准"，感知最优的模型"锐但可能编造"。工作台必须让用户在**保真**与**观感**之间显式选择（提供 PSNR 优先/感知优先两档），并对"生成式复原"标注"内容为模型推断，不可用于取证"。

## 4. 高层视觉任务（L3–L4）

### 4.1 任务定义与技术范式总表

| 任务 | 输入→输出 | 核心难点 | 主流范式 | 代表模型 | 指标 |
|---|---|---|---|---|---|
| 图像分类 | 图 → 标签/概率 | 类内差异、细粒度、长尾 | 骨干+全局池化+分类头；CNN / ViT / ConvNeXt | ResNet、EfficientNet、ViT、Swin、ConvNeXt | Top-1/5、mAP |
| 目标检测 | 图 → (框, 类, 分) | 尺度变化、密集遮挡、小目标 | 两阶段 / 单阶段锚框 / 无锚 / 集合预测 | Faster R-CNN、RetinaNet、YOLO 系列、FCOS、DETR、Grounding DINO | AP@[.5:.95] |
| 语义分割 | 图 → 逐像素类别 | 上下文、边界精度 | 全卷积 / 编码解码 / 空洞卷积 / Transformer | FCN、U-Net、DeepLabv3+、SegFormer、Mask2Former | mIoU、Boundary IoU |
| 实例分割 | 图 → 每实例掩码 | 实例区分、重叠 | 检测+掩码分支 / 查询式 | Mask R-CNN、YOLACT、SOLO、Mask2Former | mask AP |
| 全景分割 | 图 → stuff+instance | 语义与实例统一 | 统一查询、双分支融合 | Panoptic FPN、Mask2Former | PQ |
| 提示分割 | 图+提示 → 掩码 | 零样本泛化 | 提示编码+掩码解码 | SAM / SAM2、MobileSAM、EfficientSAM | IoU、零样本迁移 |
| 关键点 | 图 → 点集+置信 | 遮挡、尺度、多人 | 热力图回归 / 自底向上关联 | HRNet、SimpleBaseline、OpenPose、ViTPose | OKS-AP、PCK |
| OCR | 图 → 文本+位置 | 弯曲文本、密集小字、多语言 | 检测（分割/回归）+ 识别（CTC/注意力） | DBNet++、EAST、CRNN、SVTR、PARSeq | Hmean、CER |
| 抠图 | 图(+trimap) → alpha | 半透明、发丝 | 三分图传播 / 端到端 | Closed-form、Deep Image Matting、ViTMatte | SAD、MSE、Gradient |
| 深度估计 | 图 → 深度图 | 尺度歧义 | 单目监督/自监督/大模型 | MiDaS、Depth Anything、Marigold | AbsRel、δ<1.25 |
| 图像描述/问答 | 图(+问) → 文本 | 视觉-语言对齐 | 编码器-解码器 / 多模态大模型 | BLIP-2、LLaVA、Qwen-VL | CIDEr、准确率 |
| 检索 | 图 → 相似图 | 语义鸿沟 | 全局/局部描述子 + ANN | CLIP、DINOv2、SuperPoint+SuperGlue | Recall@K、mAP |

### 4.2 分类

- **范式**：`骨干网络（特征）→ 全局平均池化 → 全连接 → Softmax`；多标签用 `BCE + sigmoid`；开集/度量学习用 `ArcFace/CosFace`。
- **关键设计**：感受野与分辨率权衡（小目标需要高分辨率与空洞卷积）、标签平滑、混合增强（Mixup/CutMix）、长尾重采样（class-balanced loss）。
- **训练技巧**：预训练迁移几乎总是优于从头训练；线性探测（frozen backbone）用于快速评估数据可分性。
- **典型失效**：背景捷径（模型学背景而非物体）→ 用遮挡测试/显著性图自查；跨域（不同相机/光照）性能骤降 → 需域增强或域适应。

### 4.3 目标检测

- **两阶段**（Faster R-CNN 系）：RPN 生成候选 → RoIAlign 对齐特征 → 分类+回归。精度高、速度慢，适合离线质检。
- **单阶段锚框**（YOLO/RetinaNet）：密集预测 + 锚框回归；Focal Loss 解决正负样本失衡。
- **无锚**（FCOS/CenterNet/YOLOv8+）：直接预测中心到边距离或热力图峰值，超参更少。
- **集合预测**（DETR 系）：Transformer 解码 + 匈牙利匹配，**免 NMS**；收敛慢需强增强与长训练。
- **开放词表**（Grounding DINO/OWL-ViT）：文本提示检测任意类别，是"零样本预标注"的基础。
- **后处理**：NMS/Soft-NMS/DIoU-NMS；置信度与 IoU 阈值是产品级参数，必须可交互调节并即时看到框数变化。
- **指标细节**：AP 是 PR 曲线下面积，按 IoU 0.5:0.95 平均；小目标（<32²）AP 通常只有大目标的一半，工作台应分组展示。

### 4.4 语义 / 实例 / 全景分割

- **语义**：FCN 开创逐像素预测；U-Net 用跳跃连接找回边界；DeepLab 用空洞卷积扩大感受野 + ASPP 多尺度；SegFormer/Mask2Former 用 Transformer 统一多尺度。
- **实例**：Mask R-CNN 在 Faster R-CNN 上加掩码分支（RoIAlign 消除量化误差）；SOLO/Mask2Former 走"查询→掩码"的免框路线。
- **全景**：stuff（天空、道路，不可数）+ thing（人、车，可数）；PQ = SQ×RQ，兼顾识别与分割质量。
- **提示分割**：SAM = 图像编码器（ViT，重）+ 提示编码器（点/框/掩码）+ 轻量掩码解码器；一次编码、多次提示，天然适配"人工点几下就出掩码"的标注场景，是标注效率的关键杠杆。
- **边界质量**：mIoU 对边界不敏感，细长结构（裂缝、血管、道路）要用 Boundary IoU、clDice 或骨架距离评估。

### 4.5 关键点检测

- **Top-down**（先检测人再回归关键点，HRNet/SimpleBaseline）精度高、速度随人数线性增长；**Bottom-up**（OpenPose 的 PAF 关联）速度恒定、拥挤场景易错连。
- **Heatmap 回归 + argmax/soft-argmax** 是主流；坐标回归（直接出 x,y）简单但精度低。
- **协议差异**：COCO 17 点、MPII 16 点、AFLW 21 点、人脸 68/106 点、手 21 点；**关键点顺序与左右语义必须绑定 schema**，否则训练/推理静默错位。
- **指标**：OKS（关键点相似度，按标注者一致性加权）+ AP；PCK 按阈值归一化距离。

### 4.6 OCR 与文档理解

- **流水线**：图像预处理（去噪、倾斜校正、去印章）→ 文本检测（DBNet 可微分二值化 / EAST / PSENet）→ 文本识别（CRNN+CTC；SVTR/PARSeq 为 Transformer 路线）→ 后处理（词典、语言模型、正则约束）→ 版面分析（PP-Structure、LayoutLMv3）→ 结构化抽取（表格、票据、公式）。
- **难点**：弯曲/旋转文本（需多边形或 Bezier 框）、密集小字、手写体、多语言混排、印章遮挡。
- **指标**：检测用 Hmean（P/R 调和），识别用准确率与 CER，端到端用"整图全对率"。产品上更该看**字段级准确率**（如发票金额）。

## 5. 生成与编码（L5）

### 5.1 图像生成

**（1）任务谱**

| 任务 | 输入 | 输出 | 关键技术 |
|---|---|---|---|
| 文生图 T2I | 文本 | 图像 | 扩散/流匹配 + 文本编码器 |
| 图生图 I2I | 图+文本+强度 | 变体图 | 加噪起点控制（strength） |
| 局部重绘 Inpaint | 图+掩码+文本 | 修补图 | 掩码潜变量重采样 |
| 扩图 Outpaint | 图+方向+尺寸 | 更大构图 | 画布外推+掩码 |
| 指令编辑 | 图+指令 | 编辑图 | InstructPix2Pix、编辑专用模型 |
| 参考生成 | 参考图/身份 | 一致风格/主体 | IP-Adapter、ReferenceNet |
| 结构可控生成 | 条件图（边缘/深度/姿态） | 服从结构的图 | ControlNet、T2I-Adapter |
| 风格迁移 | 内容图+风格图 | 风格化图 | AdaIN、StyTr²、扩散编辑 |
| 超分/修复 | 低质图 | 高质图 | 见 §3.4 |

**（2）范式演进**

- **GAN**：生成器与判别器对抗；StyleGAN 的潜空间解耦使其成为人脸/素材生成的重要基线，缺点是模式覆盖不全、训练不稳。
- **VAE**：变分下界 + 重参数化，潜空间连续可插值，但易模糊；今天主要作为扩散的"压缩器"（LDM 的 VAE）。
- **扩散**：前向加噪 `q(x_t|x_0)`，反向学习噪声 `ε_θ`；DDIM 加速采样；**LDM** 把扩散搬到 VAE 潜空间，使高分辨率可行；**classifier-free guidance** 用条件/无条件两支外推提升服从度（guidance scale 是最重要的"听话程度"旋钮）。
- **DiT / 流匹配**：用 Transformer 替换 UNet 骨干；rectified flow 把噪声→数据的路径拉直，少步采样质量更好（SD3、Flux 路线）。
- **自回归视觉 token**：VQ 离散化 + 序列建模，与语言模型同构，是"统一多模态"的一条主路。

**（3）可控性清单**（决定生成能否进生产）

`结构控制（canny/depth/pose/lineart/seg）→ 区域控制（掩码+分区提示）→ 身份/风格控制（LoRA/IP-Adapter）→ 布局控制（框/gligen）→ 参数控制（seed/CFG/steps/scheduler）`

**（4）评价与合规**

- 自动：FID/KID（分布距离）、CLIPScore（图文一致性）、ImageReward/HPS（人类偏好代理）。
- 人工：成对偏好胜率、指令遵循率、身份一致性（ID 保持相似度）。
- 合规：生成内容须写入不可见水印 + C2PA 元数据；人脸/商标/版权风格需审核开关；**不得用于伪造证件、虚假证据**。

### 5.2 图像压缩编码

| 环节 | 技术 | 说明 |
|---|---|---|
| 变换 | DCT（JPEG）、小波（JPEG2000）、帧内预测+变换（AV1/HEVC） | 去相关，把能量集中到少数系数 |
| 量化 | 量化表/QP | **唯一有损环节**，决定码率-质量曲线 |
| 熵编码 | Huffman、算术编码、rANS、CABAC | 无损压缩概率冗余 |
| 预测 | 帧内方向预测、帧间运动补偿 | 视频与 AVIF/HEIC 的核心增益 |
| 率失真优化 | RDO、λ 权衡 | 编码器的"聪明"之处 |
| 学习式编码 | 自编码器+超先验+上下文模型、GAN/扩散感知损失 | 低码率下感知质量更优，但复杂度高 |
| 工程手段 | 色度下采样 4:2:0、渐进式、瓦片切分、ROI 编码、金字塔缩略图 | 决定"能不能用"的往往是这些 |

**指标**：BD-rate（同等质量下的码率节省）、PSNR/SSIM/LPIPS、编解码耗时。工程上真正要看的是**体积-质量曲线**，而不是单一质量因子。

### 5.3 特征提取与检索

- **全局描述子**：颜色直方图、GIST、BoW/VLAD/Fisher Vector → CNN 全局池化（GeM）→ **CLIP/DINOv2 嵌入**（当前默认）。
- **局部描述子**：SIFT/SURF/ORB → SuperPoint + SuperGlue → LoFTR（无检测器，弱纹理场景更强）；用于匹配、拼接、定位、复制检测。
- **哈希**：aHash（均值）、dHash（梯度）、pHash（DCT 低频），用于**近重复检测**与版权比对；对裁剪/旋转鲁棒性有限，需配合局部特征。
- **向量检索**：HNSW（图索引，高召回低延迟）、IVF-PQ（量化，省内存）；归一化后余弦相似度；库选 FAISS / Milvus / Qdrant。
- **应用**：以图搜图、文本搜图（CLIP）、重复图清理、数据集去泄漏（训练/测试近重复是精度虚高的头号元凶）、聚类与难例挖掘。

# 第二部分　图像全流程工作台软件方案

## 6. 产品定位与设计原则

### 6.1 一句话定位

**一个本地优先的图像全流程工作台：把"看图 → 调图 → 标图 → 训模型 → 验模型 → 出图"收进同一个数据模型里，中间不做格式往返。**

现有开源工具各自都很强，但彼此断裂：调图在 GIMP/darktable，标注在 labelImg/CVAT，训练在 Ultralytics/MMDetection，评测在 FiftyOne，生成在 ComfyUI。**每一次跨工具都是一次导出、一次语义丢失、一次版本错位**。本方案的核心价值不是"再造一个标注工具"，而是**用一条资产血缘把六个环节焊住**。

### 6.2 目标用户与场景

| 角色 | 核心诉求 | 高频动作 |
|---|---|---|
| 算法工程师 | 快速验证想法、批量跑数据处理、训练与对比 | 写处理链、跑实验、看指标、导出 ONNX |
| 标注/质检员 | 快速、少点击、有 AI 辅助 | 点选 SAM、复用上帧、复核冲突 |
| 科研/工程分析 | 精确测量、可复现、出图规范 | 标定、测量、统计、导出高 DPI 插图 |
| 内容生产者 | 生成、局部修改、批量出图 | 文生图、重绘、超分、压缩导出 |
| 团队负责人 | 进度、质量、权限、可追溯 | 看板、审计、模型版本对比 |

### 6.3 八条设计原则

1. **能力可编排**：任何单步操作都是一个**算子（Operator）**，可独立调用，也可拼成 DAG。没有"只能点按钮不能批处理"的功能。
2. **参数可视化、结果可对比**：每个参数有物理含义、范围、默认值与实时预览；任何处理都能 A/B 对比。
3. **一切可复现**：产物由 `输入哈希 + 算子版本 + 参数 + 随机种子 + 环境指纹` 唯一决定，重跑必得同一结果。
4. **非破坏编辑**：处理链是"配方（Recipe）"而非"覆盖保存"，随时回退、分叉、参数回溯。
5. **本地优先、渐进协作**：单机零依赖可用；需要多人时再挂服务端，数据模型不变。
6. **专业正确性优先**：色彩空间、位深、坐标约定、值域这些"看不见的契约"必须显式化，宁可多一步提示，不做静默猜测。
7. **可视化即功能，不是包装**：没有画面、没有前后对比、没有过程节点展示的能力，一律视为未交付（详见 §8）。
8. **按键化优先**：一切都是可见的按钮与快捷键，命令行只是出口而非入口；用户不写代码即可走完全流程（详见 §8.7）。

## 7. 总体架构

### 7.1 五层架构

| 层 | 组成 | 职责 | 关键约束 |
|---|---|---|---|
| 表现层 | Qt 6（Widgets 面板 + Quick/QRhi 画布）、自研图层合成与着色器 | 交互、渲染、参数面板、大图视口 | **不与计算同线程**，只发命令、只画结果 |
| 应用层 | 命令总线（Command/Undo）、Taskflow DAG、状态机、任务队列 | 编排、调度、事务、撤销 | 所有变更走命令对象，可撤销、可审计、可序列化为 Recipe |
| 能力层 | `ft_ops` 算子库（OpenCV/libvips）、`ft_ml`（ONNX Runtime 推理）、`ft_bridge`（训练服务进程管理）、`ft_io`（OpenImageIO/LibRaw/GDCM） | 像素与推理计算、编解码 | 算子声明 schema 与版本；C++ 只做推理，训练交给 Python worker |
| 数据层 | SQLite（单机 WAL）/ PostgreSQL（团队）、CAS 内容寻址仓库、hnswlib 向量索引 | 资产、版本、血缘、索引 | 原图**只存一份**，派生物按哈希引用 |
| 基础设施 | oneTBB 线程池、GPU 上下文池、spdlog、Crashpad、CMake + vcpkg | 稳定运行 | 训练在**独立进程**中，与交互彻底隔离 |

### 7.2 数据流（单向主干，允许回溯）

`导入 → 解析属性 → 资产入库(CAS) → [处理链] → 派生资产 → [标注] → 标注集 → [数据集快照] → [训练] → 模型版本 → [推理] → 结果集 → [评测报告] → 回流标注（主动学习）`

这条主干上的每个节点都是**不可变对象 + 版本指针**，任何一步都能分叉出实验分支，互相不污染。

### 7.3 三种部署形态

| 形态 | 组成 | 适用 | 说明 |
|---|---|---|---|
| 单机（默认） | Qt 单体 + SQLite + 本地 CAS + 本地 GPU；训练为可选 Python 组件 | 个人、离线、涉密 | 主程序零 Python 依赖；装训练组件才出现「训练」页 |
| 团队 | 同一二进制 `--server` 模式（HTTP/WebSocket）+ PostgreSQL + MinIO + 推理节点 | 5–50 人协作 | 桌面与服务端**同一套 C++ 核心代码** |
| 混合 | 本地交互 + 远端训练 worker（gRPC） | 数据敏感但算力不足 | 只上传处理配方与特征，不回传原图 |

### 7.4 进程与资源隔离

- **UI 进程**：只管渲染与交互，永不阻塞。
- **算子进程池**：CPU 密集，按 CPU 核数并行，支持取消与超时。
- **模型进程**：独占 GPU，常驻加载（避免反复初始化），按显存排队。
- **训练进程**：独立 Python worker（独立环境、独立队列与显存配额），可与主程序同机或跨机；与推理互斥或分卡。
- **隔离理由**：一次 OOM 或死循环不能带走整个应用；这是"能长时间跑批"的前提。**Python worker 崩溃只损失一个任务**，主程序照常可用，这是混合架构最实在的收益之一。

## 8. 全流程可视化与按键化（贯穿全文的硬约束）

> 这一章是**产品约束**，不是功能建议。它规定了"什么算做完"：能力接进后端不算完，必须在界面上有按钮、有画面、有对比。
> 一句话：**用户不写一行代码、不打开第二个软件，就能从一张原图走到一个可用的模型和一批可交付的图，并且每一步都看得见前后差别。**

### 8.1 三条不可妥协的产品约束

| 编号 | 约束 | 定义 | 反例（视为未交付） | 验收判据 |
|---|---|---|---|---|
| **P1** | 全程可视化 | 任何一次计算都必须有一个"看得见"的载体：面板、覆盖层、曲线、缩略图或图谱 | 算子只在日志里输出"done"；训练只有一行 loss 数字 | 每个算子在界面上有节点、有预览、有耗时 |
| **P2** | 全程可对比 | 任何改变像素的操作，都能**一次点击**切到"处理前 / 处理后"，并在同一视口、同一缩放、同一色彩配置下比较 | 只有"结果图"，想看原图要靠重新导入或撤销 | 对比模式全局常驻，切换 ≤1 次点击、≤120ms |
| **P3** | 全程按键化 | 全部能力必须有图形入口（按钮/菜单/快捷键）；命令行与脚本是**增强**，不是前提 | "高级功能请运行 `python run.py --config ...`" | 5 个典型剧本可用纯 GUI 走完（见 §8.9） |

**为什么把这三条单列**：它们在架构里没有对应模块，却决定产品成败。技术能力是"能算"，可视化是"敢用"，按键化是"用得动"。三者缺一，工作台就退化成一组脚本的皮肤。

### 8.2 全流程总线：一条链、七个状态、零中转

界面顶部常驻**步骤条**，它同时是导航、进度条和状态机指示灯：

| 状态 | 进入条件 | 主按钮（永远只有一个） | 产物 | 完成判据 |
|---|---|---|---|---|
| S0 空 | 打开应用 | **导入图像 / 载入示例图** | 资产 | 至少 1 张资产入库 |
| S1 已导入 | 有资产 | **开始处理** | 属性快照、直方图、缩略图 | 属性解析完成 |
| S2 已处理 | 处理链非空且已执行 | **前往标注** | 处理结果 + 配方 | 结果可对比、可导出 |
| S3 已标注 | 标注数 ≥1 | **训练模型** | 标注集 | 至少 1 类有 ≥2 个样本 |
| S4 已训练 | 模型存在 | **运行推理** | 模型版本 | 推理出 ≥1 个结果 |
| S5 已推理 | 有推理结果 | **导出结果** | 检测结果集 | 结果可回灌标注 |
| S6 已导出 | 有导出产物 | **新建任务 / 继续迭代** | 文件 + 清单 + 配方 | 清单可追溯 |

**四条总线规则**

1. **按钮可用性由状态驱动**：不满足前置条件的按钮直接禁用并给出原因（hover 提示"需先完成标注"），而不是点了报错。**不给无效按钮**是按键化的第一原则。
2. **阶段之间传引用，不传文件**：处理结果、标注、数据集、模型都是同一资产的不同版本（对应 §10 的资产血缘），避免"导出→再导入"的语义丢失。
3. **回退不销毁**：改处理参数后，下游的标注与模型标记为 `stale`（灰显 + "需重跑"角标），但数据保留，随时可对比新旧。
4. **下一步永远可见**：每个状态右上角有一个高亮的主按钮，用户不需要记住流程，跟着按钮走即可。

### 8.3 图形化的四个层次

| 层次 | 呈现形式 | 交互 | 解决的问题 |
|---|---|---|---|
| **L1 面板化** | 左（能力）/ 中（画布）/ 右（属性）三栏固定 | 栏位不跳动，切换阶段只换左栏内容 | 肌肉记忆，降低学习成本 |
| **L2 节点化** | 处理链以**节点列表 / DAG** 呈现，每节点显示算子名 + 关键参数摘要 | 拖拽排序、折叠展开、单击禁用、右键复制、分支并行 | 让"处理过程"本身可见，而不是黑箱 |
| **L3 图层化** | 画布上叠加：标注、检测框、掩码、测量线、网格、十字线、直方图窗口 | 每个图层独立开关、独立透明度、独立颜色 | 同一画面承载多种信息而不互相遮挡 |
| **L4 图谱化** | 资产血缘图：原图 → 派生 → 标注 → 数据集版本 → 模型 → 导出 | 点击任意节点跳转到对应工作区，显示"由谁、用什么参数、何时产生" | 解决"这张图是怎么来的"这一根本问题 |

**节点即文档**：处理链的节点本身就是说明书。用户看到 `① 缩放 0.6× ② 双边滤波 r=3 ③ CLAHE 2.0`，无需读帮助文档就知道发生了什么。节点顺序错误时（例如先锐化后降噪），系统给出**黄色提示**而非阻止——专业工具要给建议，不给枷锁。

### 8.4 前后对比引擎（产品核心，最高优先级）

#### 8.4.1 五种对比模式

| 模式 | 画面 | 适用 | 交互细节 |
|---|---|---|---|
| **并排** Side-by-side | 左右各一幅，中间分隔 | 整体观感、构图变化 | 两幅**同缩放同平移**，禁止各自 fit（否则比较失真） |
| **分割** Split | 一幅画面，一条可拖动的分界线，左原图右结果 | 局部细节、边缘、纹理 | 拖动分界线；`←/→` 微调 1px；双击复位 50%；分界线两侧显示 A/B 角标 |
| **差异** Diff | `abs(A−B)` 逐通道取绝对值，按增益放大，热度着色 | 找"到底改了什么"、验证参数是否生效 | 增益 ×1–×16；可只显示超阈值差异；几何变化时先把 A 重采样到 B 尺寸 |
| **闪烁** Flicker | A/B 以 1–8 Hz 交替 | 察觉微小位移、色偏、抖动 | 空格暂停/继续；频率可调；暂停时保留当前帧 |
| **洋葱皮** Onion | B 叠在 A 上，B 的不透明度 0–100% | 配准、拼接、修图接缝 | 滑杆控制透明度；支持差值混合 |

模式切换常驻在画布左上角，**任何阶段都可调用**（处理时用它看效果，标注时用它看原图，推理时用它看前后）。

#### 8.4.2 对比的"公平性"七条规则（不做就会得出错误结论）

1. **同缩放**：对比视图共享一个缩放与平移矩阵，两侧不允许各自适应窗口。
2. **同色彩配置**：两侧用同一 ICC 渲染路径；不得一侧 sRGB 一侧线性。
3. **同插值**：放大时两侧用同一插值核，否则"哪边更清晰"是插值造成的假象。
4. **同裁切**：几何变换后按结果尺寸对齐，只比较重叠区，并显式标注"仅比较重叠区域"。
5. **像素对齐**：1:1 模式下像素边界对齐，不做半像素偏移。
6. **无遮挡**：对比时可一键隐藏所有标注/网格/参考线，只留像素。
7. **可量化**：观感之外必须给数字，避免"看起来差不多"。

#### 8.4.3 量化条（始终可见）

`PSNR ↑ · SSIM ↑ · MAE ↓ · 变化像素占比 % · 处理耗时 ms`

- 参数变化时实时重算（代理分辨率上，≤120ms）。
- 数值旁给出**方向语义**（↑ 越大越好 / ↓ 越小越好），不要求用户懂公式。
- 点击任一指标 → 展开解释卡：定义一句话 + 本次数值 + 与上一组参数的对比。

#### 8.4.4 像素探针

鼠标处同时读出 **A 与 B 同坐标**的值：`(x,y) A:RGB(123,98,77) B:RGB(140,110,82) Δ=(+17,+12,+5) ΔE00=6.4`。

- `ΔE00 > 2` 标黄（人眼可辨），`> 5` 标红（明显差异）。
- 支持钉住 2–4 个采样点做"定点跟踪"，参数调整时看这几个点的数值怎么变——这是调参最有效的手段。
- 显示局部 5×5 邻域均值，避免单像素噪声误导。

#### 8.4.5 直方图叠加

A 用灰色填充、B 用类别色描边，同一坐标系叠加；可切 RGB / 亮度 / Lab 的 L。
一眼看出"提亮是否压死了高光""去噪是否削掉了暗部层次"——比看画面更早发现过度处理。

#### 8.4.6 几何变化时的对齐策略

| 情形 | 策略 |
|---|---|
| 同尺寸（滤波/色彩） | 直接逐像素比较 |
| 尺寸变化（缩放/裁剪） | A 重采样到 B 尺寸后比较，并标注"已重采样对齐" |
| 画幅变化（旋转/扩边） | 默认只比较重叠区，可切换"补边后比较" |
| 通道变化（灰度/二值） | 提升到 RGB 后比较，或切"仅亮度通道" |

#### 8.4.7 性能预算

| 动作 | 预算 | 手段 |
|---|---|---|
| 切换对比模式 | ≤50ms | 结果预渲染到离屏画布，切换只换合成方式 |
| 拖动参数滑块到画面更新 | ≤120ms（1MP 代理） | 代理分辨率 + 结果缓存 + rAF 合并 |
| 拖动分割线 | 60fps | 只重绘合成层，不重跑处理 |
| 计算差异图 | ≤80ms（1MP） | 逐像素绝对差 + LUT 着色 |
| 全分辨率重算 | 用户显式触发 | 进度条 + 可取消 + 完成后自动进入对比 |

### 8.5 进度、反馈与长任务（"在跑"和"还要多久"都要可见）

> 图像工作台的每一次操作都可能很慢：一张 4 亿像素图要解码十几秒，一批 5 万张要跑几十分钟，一次训练要几小时。**没有进度，用户就不知道软件是死了还是在干活**——这是工具类软件最常见的劝退点，比功能少更致命。

#### 8.5.1 按耗时给四种反馈，不要一律转圈

| 时长 | 典型操作 | 反馈形式 | 必须可取消 |
|---|---|---|---|
| **< 300 ms** | 参数微调、切换对比模式、选中标注 | 即时状态变化（按钮按下态、画面刷新、微动效） | 不需要 |
| **0.3–3 s** | 应用单个算子、打开 1 万像素小图 | 内联细条（在触发按钮或列表项上）+ 转圈 | 不必 |
| **3 s–2 min** | 全分辨率重算、单张导出、自动预标注 | **确定性进度条 + 已处理/总数 + 剩余时间** | 必须 |
| **> 2 min** | 批量处理、建索引、训练、大图金字塔 | **任务中心 + 分阶段进度 + 后台继续工作 + 完成通知** | 必须，且支持暂停/续跑 |

规则：**任何超过 3 秒的操作都不允许只显示一个无限旋转的圈**。转圈只回答"还活着"，不回答"还要多久"。

#### 8.5.2 进度的三种形态

| 形态 | 何时用 | 呈现 | 示例 |
|---|---|---|---|
| **确定性** | 总量已知（文件数、像素块、epoch） | 百分比 + 已处理/总数 + ETA | `1 240 / 5 000 张 · 42% · 约 3 分 20 秒` |
| **分阶段** | 总量未知但阶段清晰 | 阶段名 + 阶段内进度（可嵌套两层） | `解码 3/5 → 解析元数据 → 建金字塔` |
| **计数式** | 无法估时但节奏可感 | `[42/100]` 或"已处理 N 项" | 编译式计数、日志流 |

**禁止假进度**：靠定时器每 500 ms 加 1%、到 95% 停住，是欺骗。用户第一次被骗，之后就再也不信任何进度条。

#### 8.5.3 成熟软件怎么做（逐条借鉴）

| 软件 | 做法 | 我们借用什么 |
|---|---|---|
| **Windows 资源管理器 / macOS Finder** | 复制对话框：总进度 + 当前文件 + 速度 + 剩余时间 + 暂停 | 双层进度（总体 × 当前项）与"暂停"而非只有取消 |
| **Chrome / Edge 下载** | 每项独立进度 + 汇总 + 速度 + 失败单项重试 + 断点续传 | 失败不整体重跑，只重试失败项 |
| **Steam** | 队列 + 分阶段（分配 → 下载 → 校验 → 安装） | 阶段化展示，让"卡在 99%"变成"正在校验" |
| **Docker pull** | 每个分层一条独立进度 + 总体进度 | 并行任务的正确可视化：多条子进度 + 一条总进度 |
| **HandBrake** | 编码队列 + fps + 帧计数 + 剩余时间 + 暂停/继续 | 吞吐量（fps、张/秒）比百分比更能反映机器状态 |
| **DaVinci Resolve / Media Encoder** | 渲染队列 + 每任务 ETA + 完成后动作（关机/打开目录） | 队列视图 + 完成动作可配置 |
| **Blender** | 状态栏左下角细进度 + `ESC` 取消 + 报告日志 | 不打断操作的小进度 + 与日志联动 |
| **Adobe Lightroom** | 导入进度 + **可继续工作** + 完成后汇总 | 长任务不锁界面，完成后给汇总而非逐条弹窗 |
| **VS Code** | `withProgress` 三档位置：通知 / 状态栏 / 窗口 | 同一任务可按重要度选择呈现位置 |
| **ffmpeg** | `-progress` 输出机器可读的 frame/fps/time/speed | 进度事件必须结构化，UI 与 CLI 共用一份 |
| **CMake / Ninja** | `[42/100]` 计数式，无 ETA 但节奏稳定 | 无法估时就给确定的分母 |
| **Git** | 进度写 stderr，可 `--progress` 解析 | 进度与日志分离，日志可归档 |

**共同点归纳成四句话**：① 一定有"已做/总数"；② 一定有速度或阶段；③ 一定能取消；④ 失败项可单独重试。

#### 8.5.4 统一进度模型（一套事件，三种呈现）

所有耗时操作都发同一种事件：

`ProgressEvent { job_id, phase, phase_index, phases_total, done, total, unit, rate, eta_s, message, level }`

| 呈现层 | 位置 | 内容 | 用途 |
|---|---|---|---|
| **行内** | 触发按钮 / 列表项 | 3px 细条 + 百分比 | 不打断当前视线 |
| **面板** | 当前工作区顶部（吸顶） | 阶段名 + 双层进度 + 取消 | 当前任务的完整信息 |
| **任务中心** | 右下角浮层 / 独立抽屉 | 全部任务（排队/运行/暂停/完成/失败）+ 汇总 | 多任务并行时的总控 |

**并行任务的总进度必须加权**（按预估工作量），不能简单平均——否则"一张大图 + 九张小图"的总进度会长期停在 90% 然后突然跳完。

#### 8.5.5 各阶段的分段进度设计

| 阶段 | 分段（phase） | 进度口径 | 备注 |
|---|---|---|---|
| 导入 | 发现文件 → 解码 → 解析元数据 → 生成缩略图 → 建金字塔 | 文件数（大图按瓦片加权） | 金字塔单独成段，因为它最慢 |
| 处理 | 每个算子一个 phase | 像素块 / 图像数 | 批处理用双层：当前图 × 当前算子 |
| 标注 | 预标注推理 | 图像数 | 保存是瞬时操作，不显示进度 |
| 训练 | 外层 epoch，内层 step | step 数 + 当前 loss | 同时显示 ETA、学习率、显存 |
| 推理 | 图像数 → 每图切片 | 图像数（大图按切片） | 滑窗推理要显示"第几片/共几片" |
| 导出 | 编码 → 写盘 → 校验 | 文件数 + 字节数 | 校验段单独显示，避免"99% 卡住" |
| 建索引 | 每 N 张一批 | 图像数 | 可后台低优先级运行 |

#### 8.5.6 ETA 与速度的计算规则（决定进度条可不可信）

1. **用滑动窗口**（最近 30–60 s 的吞吐）推算剩余时间，不用全程平均——全程平均会被开头慢的首项拖偏。
2. **样本不足 10 个时显示"估算中…"**，先给已处理数，不要给一个乱跳的数字。
3. **剩余 > 1 小时给预计完成时刻**（"约 15:40 完成"），< 1 分钟给秒数，中间给"约 N 分钟"。
4. **进度不得倒退**。重试或重新计算时必须显式说明"第 2 次尝试"，而不是让百分比往回跳。
5. **停在 99% 要有解释**：把最后一段命名为"写入磁盘 / 校验 / 合并结果"，让用户知道不是卡死。
6. **更新节流到 10 Hz**：底层每处理一张图就回调一次会把 UI 线程打满，进度反而卡。

#### 8.5.7 系统级集成与后台化

| 能力 | 做法 | 参考 |
|---|---|---|
| 任务栏 / Dock 进度 | Windows `ITaskbarList3::SetProgressValue`；macOS `NSDockTile` 角标 | 资源管理器、Chrome |
| 完成/失败通知 | 系统通知 + 应用内消息中心，点击直达产物 | Lightroom、VS Code |

| 断点续跑 | 任务日志 + 已处理清单落盘，重启后可续 | 下载器、HandBrake |

#### 8.5.8 交互细节（容易被忽略但用户天天遇到）

- **主按钮就地变"取消"**：任务运行时，原来的"开始处理"按钮变成"取消"，位置不动，用户不用找。
- **取消要二次确认**（> 10 s 的任务），并说明"已完成的部分会保留"。
- **取消要真的停**：不能等当前批次跑完才响应；每张图之间检查取消标志。
- **失败项单独重试**：批量 5000 张失败 3 张，只重跑这 3 张。
- **完成后可直达**：提供"打开所在文件夹""在对比视图查看"两个动作。
- **数字与图形并存**：进度条旁必须有百分比文字，色盲用户与截图沟通都靠它。
- **可折叠**：任务中心默认收起为一行摘要（"2 个任务运行中"），不遮挡画布。

#### 8.5.9 进度相关的反模式

| 反模式 | 用户感受 | 正确做法 |
|---|---|---|
| 无限转圈超过 3 秒 | "是不是死了" | 给分母或阶段 |
| 假进度（定时器凑数） | 被骗一次就不再信 | 只报真实计数 |
| 只有总进度没有当前项 | 不知道卡在哪 | 双层进度 |
| 完成后无提示 | 不知道好了没有 | 通知 + 汇总 |
| 取消按钮无响应 | 感觉失控 | 检查点轮询取消标志 |
| 后台任务找不到入口 | 任务"消失" | 常驻任务中心 |
| 99% 长时间不动 | 以为崩溃 | 末尾分段命名 |
| 进度更新过频导致卡顿 | 越跑越卡 | 10 Hz 节流 + 批量合并 |

#### 8.6.4 参数控件规范

任何参数都要满足五件套：**滑块（粗调）+ 数字输入（精调）+ 方向键（1 步进）+ 单位 + 重置为默认**。
禁止出现：只有数字框没有滑块（不敢拖）、只有滑块没有数字（无法复现）、参数无单位（不知道量纲）、参数无默认值（不知从哪开始）。

#### 8.6.5 零脚本原则

- GUI 功能集必须是 CLI 功能集的**超集或等集**，不允许"界面做不到请写脚本"。
- 反过来，任何一个 GUI 动作都能**一键导出为 Recipe**（JSON），供批处理与自动化复用（对应 M11）。
- 提供"复制为命令"按钮：把当前操作翻译成 CLI 一行，便于进流水线——但这是**出口**，不是**入口**。

#### 8.6.6 键盘可达与焦点可见

Tab 顺序遵循"左栏 → 画布 → 右栏"，焦点环 2px 蓝色可见；所有按钮有 `aria-label`；标注、缩放、对比必须能纯键盘完成——这是无障碍要求，也是熟练用户的效率来源。

### 8.9 验收标准（可量化，写入产品验收）

1. **零脚本完成率 100%**：§11 的四个剧本，全部可用纯 GUI（鼠标 + 键盘）走完，不出现终端。
2. **对比可达性 ≤1 次点击**：任意像素算子生效后，切到"处理前/后"对照不超过 1 次点击或 1 个快捷键。
3. **首次可用时间 ≤3 分钟**：新用户从打开应用到导出第一张处理图（含示例图路径）不超过 3 分钟。
4. **反馈时延**：滑块到画面 ≤120ms（1MP 代理）；模式切换 ≤50ms；批量任务有可见进度与剩余时间。
5. **可追溯 100%**：任意产物都能在血缘图中定位到"输入 + 算子 + 参数 + 时间 + 操作者"。
6. **无效按钮为 0**：任何时刻界面上的按钮要么可点，要么禁用并说明原因。
7. **进度可信**：任何 >3 s 的操作都有确定分母或明确阶段；继续 >10 s 的操作可取消，取消响应 ≤1 s；批量任务失败项可单独重试。
8. **后台不阻塞**：>2 min 的任务在后台运行期间，画布仍可缩放、对比、切换图片，UI 帧率不低于 30fps。
9. **对比结论一致**：同一组参数，两人用对比视图得出的"是否改善"结论一致率 ≥90%（说明对比是客观的，不是观感玄学）。

### 8.10 常见反模式（明确禁止）

| 反模式 | 后果 | 正确做法 |
|---|---|---|
| 只在日志里报告"处理完成" | 用户不敢用 | 必须有画面 + 耗时 + 尺寸变化 |
| 对比时两侧各自适应窗口 | 大小不同，结论错误 | 共享缩放矩阵 |
| 参数只有滑块没有数字 | 无法复现 | 五件套控件 |
| 处理链藏在"高级设置"里 | 过程不可见 | 节点常驻可见 |
| 批量任务只有转圈没有进度 | 无法预估 | 进度 + 已完成/总数 + 剩余时间 + 可取消 |
| 二次确认弹窗满天飞 | 点击疲劳 | 只有破坏性操作才确认 |
| 功能靠命令行补全 | 门槛劝退 | GUI 功能集 ⊇ CLI |

## 9. 功能模块设计

> 模块编号 M1–M12，每个模块标注对应第一部分的章节，确保能力无遗漏。

### M1 资产导入与全量属性解析　`↳ 对应 §2.1 §2.2 §2.3`

**目标**：任何来源的图，进来就能被正确理解，且属性一条不漏。

| 功能 | 实现要点 |
|---|---|
| 单张/多选/文件夹递归拖入 | 文件监听 + 增量扫描；跳过隐藏与临时文件 |
| 压缩包/URL/剪贴板/相机采集/扫描仪 | ZIP 流式解包；HTTP 拉取带校验；TWAIN/WIA 可选 |
| 专业格式解析 | RAW（LibRaw）、DICOM（GDCM，含窗宽窗位与匿名化）、多页 TIFF（libtiff）、PSD 分层（自研解析）、EXR（OpenEXR）、SVG（resvg 光栅化预览） |
| **方向自动校正** | 读 EXIF Orientation 并立即应用，写回时归一化为 1，避免"导入躺倒" |
| 超大图金字塔 | 生成多级瓦片（等价 DZI），视口按需解码，内存恒定 |
| 属性面板（全量） | 尺寸/宽高比/位深/通道数/色彩空间+ICC 名称/DPI/格式与压缩参数/文件体积/EXIF 全字段/GPS/哈希/直方图/RGB 均值与方差/锐度（拉普拉斯方差）/噪声估计/是否含 alpha/动画帧数/是否渐进式 |
| 入库校验 | 截断/损坏检测、色彩配置缺失、异常尺寸、重复（pHash + 内容哈希）、隐私风险（人脸/证件） |
| 幂等与去重 | 内容哈希做主键；同一文件重复导入不产生新资产 |

**验收**：导入 1 万张混合格式图像，属性解析成功率 ≥99%，EXIF 方向 100% 正确，重复识别准确率 ≥98%。

### M2 查看与检查（Inspector）　`↳ 对应 §2.2 §2.4 §8.4`

**目标**：把"看图"做成可测量的专业动作，而不是缩略图滑动。

- **视口**：GPU 加速缩放/平移/旋转，1:1 像素对齐，缩放级别显示实际倍率；平滑缩放与最近邻（检查像素）一键切换。
- **像素探针**：鼠标处实时显示坐标、RGB/HEX/HSV/Lab 值、局部 5×5 邻域；支持多点取样与差值。
- **多图对比**：并排 / 叠加（不透明度）/ 差异图（绝对差、增益差）/ 闪烁对比 / 滑动分割线；对比必须"同视口同缩放"。
- **分析视图**：RGB 与亮度直方图（对数刻度）、波形图、矢量示波器（视频/色彩）、通道分离、伪彩映射、等值线。
- **测量**：像素→物理单位标定（标尺/已知长度），支持长度、角度、面积、计数；结果可导出 CSV；标注与测量共享坐标系。
- **色彩检查**：ICC 软打样、色域越界警告、色盲模拟、ΔE 色差对比。
- **质量体检**：模糊度、曝光过度/不足、噪声水平、压缩伪影，输出"问题清单"并可一键跳转修复算子。

**验收**：4 亿像素图打开到可交互 <2s（金字塔）；像素取值与 OpenCV 读取结果逐位一致。

### M3 处理工作台（Processing Studio）　`↳ 对应 §3.1 §3.2 §3.3 §3.4 §8.4`

**目标**：把第一部分 L2 的**全部算子**变成可调用、可调参、可批量、可复现的工具。

**（1）算子模型（统一的四段式 schema）**

| 段 | 内容 | 示例 |
|---|---|---|
| 声明 | 名称、分类、版本、输入输出规格（通道/位深/值域/色彩空间） | `resize@1.2`：RGB8 → RGB8 |
| 参数 | 类型、范围、默认值、单位、联动规则、专家模式开关 | `scale=0.5`、`kernel=lanczos3` |
| 执行 | 纯函数语义（不修改输入），可流式/分块 | libvips 流式；OpenCV 分块 |
| 元数据 | 计算成本估计、是否可 GPU、是否改变几何（需同步标注） | `geometry=true` |

**（2）算子分组（与 §3 一一对应，全量落地）**

| 组 | 算子清单 |
|---|---|
| 几何 | 缩放（6 种插值）、裁剪（自由/比例/中心/智能）、填充（5 种模式）、旋转/翻转、仿射、透视、重映射、镜头畸变校正、相机标定、极坐标展开、拼接、内容感知缩放、网格变形 |
| 色彩 | 空间转换（ICC）、曝光/亮度/对比度/伽马、色阶与曲线、HSL 调节、白平衡（4 种）、3D LUT、色彩迁移、色调映射、色彩分级、通道运算、伪彩、色彩量化 |
| 滤波 | 均值/高斯/中值/双边/导向/NLM/BM3D、锐化（USM/拉普拉斯）、形态学全套、边缘（Sobel/Canny/LoG）、直方图均衡/CLAHE/规定化、Retinex/同态/自适应伽马、频域滤波、小波去噪、超像素、连通域 |
| 复原 | 去噪（传统+深度）、去模糊、去雾、去雨、去反光、去摩尔纹、超分（保真/感知两档）、修复补全、老照片修复、上色、图像翻译 |
| 变换类 | 灰度化、二值化（Otsu/自适应/Sauvola）、位深转换、色彩空间批量转换、Alpha 处理、通道合并 |

**（3）交互**

- **实时预览**：先对降采样代理图执行（≤1MP），参数落定后全分辨率重算；拖动滑块时 debounce 80ms。
- **A/B 对比**：左右分割、上下分割、差异高亮；"原图/结果/差异"三态切换。
- **参数面板**：基础/高级两档；每个参数带说明与"为什么这样调"的提示；预设（Preset）可保存复用。
- **撤销/重做**：命令栈（非破坏），支持 100 步以上；历史面板可跳转到任意步。
- **处理链（Recipe）**：算子按序或按 DAG 编排；中间结果可命名复用；支持分支（对不同区域不同处理）；可导出为 JSON、可由 CLI/SDK 重放。
- **批量执行**：选目录/选数据集 → 套用 Recipe → 队列执行；失败项单独列出并支持重试；支持断点续跑与"仅处理变更文件"。

**验收**：单算子参数调整到预览刷新 <150ms（1MP 代理）；10 万张批处理可无人值守跑完并有完整日志；同一 Recipe 重跑结果哈希一致。

### M4 标注工作台（Annotation）　`↳ 对应 §4.1–§4.6`

**目标**：一套界面覆盖全部视觉任务的标注，且 AI 辅助把点击次数降到最低。

| 任务类型 | 工具形态 | 关键能力 |
|---|---|---|
| 图像分类 | 标签面板（单/多标签/层级） | 快捷键 1–9、模糊搜索、最近使用、批量套用 |
| 目标检测 | 矩形框、旋转框（OBB）、点、折线 | 吸附边缘、复制上一框、批量复制到后续帧、越界裁剪 |
| 语义/实例分割 | 多边形（自动闭合）、画笔/橡皮、魔法棒、超像素吸附 | **SAM 点/框提示出掩码**、掩码布尔运算（并/交/差）、孔洞填充、边缘精细化 |
| 全景分割 | 语义层 + 实例层双轨 | stuff 与 thing 关联、遮挡关系 |
| 关键点 | 点组 + 骨架连线 + 可见性标记 | 关键点 schema 绑定（COCO17/人脸68/手21）、对称点校验 |
| OCR | 四点/多边形文本框 + 转写 | 自动预标注、字符级校对、阅读顺序 |
| 抠图 | trimap 辅助 + alpha 边缘修正 | 发丝级笔刷、前景背景涂鸦 |
| 视频/序列 | 帧序列 + 跟踪插值 | 单帧标注→前后向传播、关键帧修正、轨迹合并 |

**AI 辅助（把标注从"画"变成"点"）**

- **SAM 系列**：一次图像编码，之后每次点击/框选都在 50ms 内出掩码；支持"点正/点负"迭代修正。
- **开放词表检测**（Grounding DINO）：输入类别名 → 全图候选框 → 人工确认，适合冷启动。
- **已有模型预标注**：选模型版本 → 阈值 → 生成候选 → 人工只做增删改。
- **主动学习**：按不确定性（分类熵、检测置信度边缘、掩码边界熵）排序，优先标"模型最不确定"的图。

**质量与协作**

- **一致性检查**：重叠框、越界框、空标签、掩码面积异常、同类框尺寸离群、漏标热区（用模型预测反查）。
- **复核流**：标注→复核→仲裁三级；冲突高亮；修改留痕。
- **协同**：任务分片（按文件/按类别）、锁定与租约、CRDT 合并或简单乐观锁；离线可标、联网合并。
- **格式**：COCO / Pascal VOC / YOLO txt / LabelMe JSON / CVAT XML / 掩码 PNG / 自定义映射器（字段级映射，不写代码）。

**验收**：单张 20 目标的检测标注 <60s；SAM 辅助下掩码标注点击次数中位数 ≤5；导出 COCO 后可被主流框架直接读取且无警告。

### M5 数据集管理（Dataset）　`↳ 对应 §4、§5.3`

**目标**：数据集是一等公民，有版本、有统计、有健康度。

- **版本快照**：数据集 = 资产 ID 集合 + 标注集合 + 划分规则；快照不可变，可 diff（新增/删除/改动）。
- **划分**：随机/分层（按类别）/按组（同源图不跨集）/时间切分；**自动泄漏检测**（pHash + 嵌入近重复），防止训练测试同源。
- **统计看板**：类别分布（长尾曲线）、框尺寸分布、宽高比分布、每类实例数、标注密度、图像质量分布。
- **清洗**：坏图、模糊、重复、标签越界、类别拼写不一致、空标注图。
- **增强流水线**：几何（翻转/旋转/缩放/裁剪/透视）+ 色彩（亮度/对比/色调/噪声/模糊）+ 混合（Mixup/CutMix/Mosaic）+ 遮挡；**框/掩码/关键点同步变换**是硬要求。
- **浏览**：按标签/属性/尺寸/质量筛选；嵌入投影（UMAP/t-SNE）可视化簇与离群；相似图检索。
- **数据卡**：来源、许可、采集条件、标注规范、已知偏差——训练前的合规与可复现依据。

**验收**：10 万图数据集统计计算 <30s；泄漏检测召回 ≥95%；增强后标注与像素严格对齐（可视化抽查 0 错位）。

### M6 训练（Training）　`↳ 对应 §4、§8.5`

**目标**：不是"通用训练框架"，而是一个**成熟的训练工作台**——选数据、划分、配参、开训、看日志、评估、入库，七步全在界面里完成，不需要打开终端、不需要改配置文件。

**主流程**：`选数据集版本 → 划分训练/验证/测试 → 配超参 → 预估资源 → 开始训练 → 实时曲线与日志 → 测试集评估 → 入库`

#### M6.1 数据集与三分划分（Step 1）

**选择**：下拉列出全部数据集版本，每项显示 `名称 · v3 · 12 480 张 · 7 类 · 上次训练：2026-11-02`。切换版本时清空已有划分，防止"用 A 数据集的划分训 B 数据集"。

| 划分方式 | 交互 | 适用 |
|---|---|---|
| 按比例 | 三根联动滑杆（train/val/test），任一根拖动其余按原比例补偿，合计恒为 100% | 通用，默认 70/15/15 |
| 按数量 | 直接填绝对张数，第三项自动补齐 | 验证集固定 500 张这类硬约束 |
| 按分组 | 选择分组字段（来源批次/设备/患者 ID/文件夹） | 医学、工业、多站点采集，**防泄漏** |
| 导入清单 | 上传 CSV（文件名 + split） | 复现已有的官方划分 |

**划分时必须看到的五张视图**

1. **三段堆叠条**：比例 + 绝对张数，一眼看出 test 是否小到没有统计意义。
2. **类别 × 划分矩阵**：热力表，每格显示该类别在该集的实例数；稀有类整列标红（"该类在 test 仅 3 个实例"）。
3. **分布对比**：尺寸、长宽比、亮度三条分布曲线叠加（train/val/test 三色），偏差大时提示"验证集偏亮，可能不代表训练分布"。
4. **泄漏检测**：pHash + 嵌入近重复跨集比对，列出可疑对（缩略图并排 + 相似度），提供"移到 train""全部移出"两个动作。
5. **抽样九宫格**：每集随机 9 张缩略图，用于肉眼确认"划分没串"。

**检查清单（开始训练前的门禁）**

| 检查项 | 判定 | 处理建议 |
|---|---|---|
| 样本量 | train < 100 或 val < 30 | 警告：指标不可信，建议增大或改用交叉验证 |
| 类别覆盖 | 某类在 val/test 缺失 | 阻止开始，改为分层抽样 |
| 类别失衡 | 最多类 : 最少类 > 20:1 | 建议类别权重或重采样 |
| 泄漏 | 跨集近重复 > 0 | 默认阻止，需显式忽略并填原因 |
| 重复图 | 同集内完全重复 | 提示去重（保留一张） |
| 尺寸离群 | 极端宽高比或超大图 | 提示预处理策略（letterbox/pad） |

**可复现**：划分使用显式随机种子，界面显示种子值并允许"固定"；划分结果作为 `DatasetVersion` 的一部分写库（见 §10），任何一次训练都能追溯到当时的确切划分。

#### M6.2 超参数配置（Step 2）

左侧手风琴分组，右侧**实时摘要卡**（"当前配置：YOLO-s · 640² · bs16 · 50 epoch · 预估 38 分钟 / 9.2 GB 显存"）。

| 分组 | 参数 | 交互要求 |
|---|---|---|
| **基础** | 任务类型、模型模板、骨干、输入尺寸、类别表、预训练权重 | 模板切换时联动推荐值，不静默重置用户已改项 |
| **优化** | 优化器、初始学习率、weight decay、momentum、梯度裁剪、AMP | 学习率用对数滑杆（1e-5～1e-1），显示科学计数法 |
| **调度** | 调度器、warmup 比例、最小学习率、总 epoch、早停 patience | 与总 epoch 联动预估曲线形状 |
| **批与资源** | batch size、梯度累积、dataloader workers、设备选择、显存上限 | 多卡时显示"等效 batch" |
| **增强** | 几何（翻转/旋转/缩放/裁剪/透视）、色彩（亮度/对比/饱和/噪声/模糊）、混合（Mixup/CutMix/Mosaic）、遮挡 | 拖动强度后**右侧样本图实时变化**，并叠加框/掩码验证对齐 |
| **损失与后处理** | 损失类型、类别权重、正负样本策略、NMS 阈值（作为推理默认值写入模型包） | 阈值改动即时显示"预计召回变化"提示 |
| **高级**（默认折叠） | EMA、dropout、冻结层、LoRA rank、分布式后端 | 标注"改动风险"等级 |

**每个参数都必须有六件套**：名称、单位、默认值、**推荐范围**、一句话解释、恢复默认。
非法组合（如 `batch × 累积 > 数据集大小`、`warmup > epoch`）在**开始前**标红并阻止，不允许"跑到一半才报错"。

**资源预估器**：根据数据集规模、输入尺寸、batch、模型规模，在开始前给出 `每 epoch 时间 / 总时长 / 峰值显存 / 磁盘产物大小`。超显存时给出三条建议（降 batch / 开 AMP / 降分辨率），并可一键应用。

**预设与模板**：`快速验证（30 epoch）/ 标准 / 高精度 / 低显存`四档预设；用户可把当前配置存为"我的模板"，下次一键套用。表单与 YAML **双向同步**，高级用户可直接编辑配置文本，切回表单不丢改动。

#### M6.3 训练执行：进度、曲线与日志（Step 3）

**顶部总进度**（双层，遵循 §8.5.5）
`第 12 / 50 轮 · 340 / 1250 步 · 约 18 分钟后完成 · 42 img/s · 显存 9.1 GB`
三个按钮：**暂停**（在 epoch 边界生效）、**中止并保存**、**强制停止**（二次确认）。

**中间的曲线面板**（可多图联动、可开关、可导出 CSV/PNG）

| 曲线 | 用途 |
|---|---|
| loss（train / val 双线） | 判断欠拟合/过拟合（两条分叉即过拟合） |
| 任务指标（mAP / mIoU / Acc） | 主进度指标 |
| 学习率 | 确认调度是否按预期 |
| 梯度范数 | 发现梯度爆炸/消失 |
| 吞吐与显存 | 发现数据加载瓶颈或内存泄漏 |

支持 EMA 平滑（0–0.99）、x 轴切 epoch/step/时间、框选放大。异常自动提示：loss 变 NaN、连续 5 轮不降、梯度范数突增——顶部黄条给"可能原因 + 建议动作"，而不是让用户自己猜。

**底部的训练日志（用户最需要的部分）**

| 能力 | 规格 |
|---|---|
| 结构化 | `时间 · 级别 · 来源 · 消息`，来源分 data/model/opt/io |
| 分级过滤 | DEBUG / INFO / WARN / ERROR 复选；支持"只看错误"一键 |
| 检索 | 关键词高亮 + 正则；按 epoch 区间筛选（点曲线某段即定位该段日志） |
| 聚合 | 每 N 步聚合一行（`step 300/1250 loss=0.842 lr=1.2e-3`），展开看原始逐条，避免刷屏 |
| 跟随 | 自动滚动到底部；用户上翻时自动暂停跟随，出现"回到最新"按钮 |
| 着色 | error 红 / warn 黄 / 指标蓝 / 用户日志默认色 |
| 落盘 | 全量写 `logs/<job_id>.log`，界面只是**视图**；崩溃或关掉软件后仍可查看 |
| 导出 | 导出当前筛选结果为 txt/csv；"打开所在文件夹" |
| 容量 | 单任务日志滚动上限 200 MB，超出归档，不丢头部 |

**样本可视化（防止"训练在跑但数据是错的"）**
每 N 步抽取一个 batch，显示**反归一化后的输入图 + 标注叠加 + 增强后效果**；train 与 val 各一组。这一栏能立刻暴露"通道顺序错""归一化用错""掩码错位"三类事故——它们不会让 loss 报错，只会让模型悄悄变差。

#### M6.4 训练后：评估与入库（Step 4）

- 训练结束自动在 **test 集**上跑一遍完整评估，产出指标卡：主指标 + 分组（按类别 / 按尺寸 / 按来源）。
- 报告包含：混淆矩阵、PR 曲线、FP/FN 图库（可筛选、可加入下轮训练集）、与基线/上一版的差值高亮。
- **守门规则**：主指标低于基线时默认**不入库**，需手动覆盖并填写原因（写入审计日志）。
- 入库产物：权重 + ONNX + `model.json`（IO 规格/类别表/默认阈值）+ 评估报告；入库前必须通过 C++ 与 Python 的**输出一致性校验**（差 <1e-3，见 §12.6）。
- 一键"去推理验证"：跳到 M7，用刚训练的模型在当前图上跑，形成闭环。

#### M6.5 实验管理

实验列表展示 `名称 / 时间 / 数据集版本 / 主指标 / 状态 / 耗时`；支持多选对比（曲线叠加 + 指标表）、一键复现（同配置同种子）、"改一个参数再跑"（继承当前配置）、备注与标签。每次实验自动记录 `代码版本 + 配置 + 数据快照 + 环境指纹`，四件套齐了才算可复现。

#### M6.6 成熟度要求（"成熟软件"的判据）

| 能力 | 要求 |
|---|---|
| 中断恢复 | 断电/崩溃后可从最近 checkpoint 继续，进度与日志不丢 |
| 参数校验 | 非法组合在开始前拦截，0 次"跑到一半才报错" |
| 资源保护 | 显存不足先自动降 batch 并提示，而不是直接 OOM |
| 多任务 | 队列 + 优先级，串行占用 GPU，不并发抢卡 |
| 日志完整 | 全量落盘、可检索、可导出，界面崩溃不影响日志 |
| 可复现 | 种子 + 数据快照 + 配置 + 环境，缺一不可 |

**验收**
1. 新用户不看文档，5 分钟内完成"选数据 → 划分 → 开始训练"。
2. 训练中任意时刻都能看到：第几轮 / 第几步 / 还要多久 / 当前主指标。
3. 日志可检索、可导出；关掉软件重开仍能查看历史日志。
4. 跨集近重复 100% 被检出并默认阻止。
5. 非法参数组合 100% 在开始前拦截。

### M7 推理与评测（Inference & Eval）　`↳ 对应 §4.1 §2.4`

- **推理入口**：单图 / 批量 / 文件夹 / 数据集 / 视频 / 摄像头流；模型可选多个版本并排跑。
- **大图策略**：滑窗切片 + 重叠 + 结果拼接（NMS 跨片合并）；类别感知的切片尺寸建议。
- **交互调参**：置信度阈值、NMS IoU、最小面积、每类阈值——**改参数即时重算并显示计数变化**，这是"能不能用"的关键体验。
- **可视化**：框/掩码/关键点/热力图/Grad-CAM；按类别着色、按置信度透明度；错误高亮（与真值对比：FP 红、FN 蓝、TP 绿）。
- **误差分析**：混淆矩阵、PR 曲线、按尺寸/类别/来源分组指标、FP/FN 图库（可筛选、可加入下一轮训练集）。
- **回归测试**：固定"守门集"，每次新模型自动跑并与上一版对比，指标下降即告警。
- **性能基准**：单图延迟、吞吐、显存峰值、不同 batch/精度（FP32/FP16/INT8）对比。
- **导出**：ONNX（含动态轴）、TensorRT、OpenVINO、CoreML、TFLite；量化（PTQ/QAT）；导出后自动做一致性校验（原模型 vs 导出模型输出差异 <1e-3）。

**验收**：阈值调节到画面更新 <200ms（100 图批量）；ONNX 导出后精度损失 <0.5% mAP。

### M8 生成工作室（Generative Studio）　`↳ 对应 §5.1`

**目标**：把生成能力接到资产与标注上，而不是另开一个孤岛。

- **模式**：文生图、图生图（strength 控制）、局部重绘（掩码来自标注层或手绘）、扩图、指令编辑、参考图生成、风格迁移、超分放大、背景替换。
- **控制**：ControlNet 组（Canny/Depth/Pose/Lineart/Seg/Normal）、布局框控制、区域提示、IP-Adapter（主体/风格参考）、LoRA 管理（加载/权重/触发词）。
- **与标注互通（差异化关键）**：用分割掩码当 inpaint 区域；用检测框当生成布局；用关键点当姿态条件；生成结果自动成为派生资产并记录提示词与参数。
- **工作流**：节点图（输入/模型/条件/采样/后处理/输出），可保存为模板、批量跑参数网格（seed × 提示词 × 强度）。
- **可复现**：seed、采样器、步数、CFG、模型哈希、LoRA 版本全部入库；同一配置重跑结果一致（同硬件同精度）。
- **合规**：生成图默认写入不可见水印 + C2PA 元数据 + 提示词记录；人脸/商标相关开关；导出时可选"标注为 AI 生成"。

**验收**：1024² 图单张生成 ≤8s（消费级 GPU）；掩码重绘边缘无明显接缝；参数网格 100 张可无人值守完成。

### M9 压缩与导出（Encode & Export）　`↳ 对应 §2.3 §5.2`

- **目标驱动导出**：给定约束（体积上限 / 质量下限 / 格式兼容矩阵 / 是否需要透明），自动搜索参数并给出候选方案曲线。
- **率失真预览**：实时显示"体积-质量"曲线（PSNR/SSIM/LPIPS 三条可选），拖动即看效果，避免盲调质量因子。
- **格式矩阵**：PNG/JPEG/WebP/AVIF/JPEG XL/TIFF/EXR/GIF/SVG/PDF；每种格式只暴露该格式真正有意义的参数（色度下采样、渐进式、量化表、压缩级别、瓦片）。
- **色彩与尺寸**：嵌入或转换 ICC（默认转 sRGB 以保证一致性）、指定 DPI 与物理尺寸（打印）、按目标像素密度重采样。
- **元数据策略**：保留全部 / 保留版权 / 全部剥离（隐私）；GPS 与人脸信息默认剥离并提示。
- **批量与命名**：命名模板（`{原名}_{算子}_{参数}`）、目录结构保持、覆盖策略、导出清单（manifest）。
- **出版/科研模式**：300/600 DPI、CMYK 预览、字体与线条清晰度检查、色盲友好校验、图注与比例尺烧录（可选）。

**验收**：同等观感下体积比默认导出小 ≥30%（AVIF/WebP 路线）；导出清单可反查每个文件的处理链。

### M10 检索与资产管理（Search & Asset）　`↳ 对应 §5.3`

- **检索方式**：以图搜图（全局嵌入）、文本搜图（CLIP）、相似区域检索（局部特征）、按属性筛选（尺寸/格式/色彩/EXIF/标签/质量分）。
- **近重复与血缘**：pHash 分桶 + 嵌入聚类，识别"同一图的不同版本/裁剪/压缩"；展示派生关系图（谁由谁生成）。
- **索引**：HNSW 增量索引；新资产入库即入队建索引；支持按项目隔离索引。
- **用途**：清理重复、找相似参考、发现标注泄漏、为主动学习挑样本、为生成找参考图。

**验收**：100 万图检索 P95 延迟 <150ms，Recall@10 ≥0.9。

### M11 工作流编排（Recipe & Pipeline）　`↳ 贯穿 §3–§5`

**目标**：把 GUI 里点出来的每一步，变成可版本化、可批处理、可 API 调用的资产。

- **节点模型**：`输入（文件/数据集/查询）→ 算子/模型节点 → 分支/合并 → 输出（资产/标注/数据集/导出）`；节点间传"图像引用 + 元数据"，不传像素副本。
- **缓存与增量**：以节点输入哈希为键缓存中间结果；只重算变更分支（这是大流水线可用的前提）。
- **触发方式**：手动、文件监听（新图入目录即处理）、定时、Webhook/API。
- **同源性**：GUI 操作、CLI 命令、C++ SDK、REST 调用**共用同一 Recipe 执行器**，不存在"界面能跑但脚本跑不了"。
- **可观测**：每个节点耗时、内存、失败原因；失败节点可单独重跑；整条链有运行报告。

**验收**：任意 GUI 操作可一键"导出为 Recipe"并在无界面环境复现同样结果。

### M12 系统治理（Governance）

- **权限**：项目/角色（查看/标注/训练/管理）、资产级共享、训练任务审批。
- **审计**：谁在何时改了哪条标注/哪个参数；模型上线记录。
- **许可登记**：数据集许可（商用/研究）、模型许可（注意 AGPL 系模型的分发约束）、生成内容合规标记。
- **存储治理**：CAS 去重、冷热分层、缓存清理策略、回收站与保留期。
- **插件体系**：算子插件（声明 schema 即注册）、模型插件（声明 IO 规格即接入）、格式插件（读写器）、导出插件（目标平台）。**这是能力可持续扩展的前提**。

## 10. 关键数据模型

> 只描述实体、字段语义与关系，不写代码。所有实体都带 `id`、`created_at`、`created_by`。

| 实体 | 关键字段 | 说明 |
|---|---|---|
| **Project** | name、root_path、label_schema_id、settings | 顶层容器，隔离权限与存储 |
| **Asset** | sha256、storage_uri、w、h、bit_depth、channels、color_space、icc_profile、format、dpi、exif、preview_uri、tileset_uri | **不可变原图**；sha256 为自然主键，天然去重 |
| **DerivedAsset** | parent_ids[]、recipe_run_id、node_id | 派生物仍是 Asset，只是带血缘 |
| **Recipe** | name、version、graph_json、schema_hash、notes | 处理/生成工作流定义，版本化 |
| **Run** | recipe_id、recipe_version、input_hash、params、seed、env_fingerprint、status、outputs、logs | 一次执行的完整证据，可复现的最小单位 |
| **LabelSchema** | task_type、classes[]（含层级与颜色）、keypoint_skeleton、attribute_schema、version | 类别与关键点协议的唯一来源，版本化 |
| **Annotation** | asset_id、schema_version、geometry（type+coords）、class_id、attributes、source（manual/auto/imported）、confidence、status（draft/reviewed/arbitrated） | 一条标注；几何与任务类型解耦 |
| **Dataset** | name、datasheet、license | 逻辑数据集 |
| **DatasetVersion** | dataset_id、asset_ids_hash、split_rule、annotation_snapshot、stats_json、leak_report | 不可变快照；训练只认版本号 |
| **Model** | name、task、io_spec（输入尺寸/通道/归一化/输出编码）、framework、license | 模型身份 |
| **ModelVersion** | model_id、weights_uri、config、train_job_id、dataset_version_id、metrics、env_fingerprint | 权重与训练证据绑定 |
| **TrainJob** | model_id、dataset_version_id、config、resources、status、artifacts | 训练任务 |
| **InferenceJob** | model_version_id、scope、params（阈值/NMS/切片）、outputs | 推理任务 |
| **EvalReport** | model_version_id、dataset_version_id、metrics、slice_metrics、confusion、gate_status | 评测报告，含守门结论 |
| **TaskAssignment** | asset_scope、assignee、status、deadline、review_records[] | 标注任务与复核流 |

**关系主干**

```
Project 1─n Asset 1─n DerivedAsset        Asset 1─n Annotation n─1 LabelSchema
Asset n─n DatasetVersion（通过快照集合）    Dataset 1─n DatasetVersion 1─n TrainJob
Model 1─n ModelVersion 1─n EvalReport / InferenceJob
Run（Recipe 的一次执行）── 产生 ──> DerivedAsset，并被 Annotation 引用
```

**三条不可破坏的约束**

1. 原图与派生物分离，原图**永不修改**；所有编辑都是新增派生资产。
2. 训练必须绑定 `DatasetVersion` + `ModelVersion`，不允许"拿当前目录训练"。
3. 标注必须绑定 `LabelSchema.version`，类别改名不追溯旧标注语义。

## 12. 技术栈（C++ 框架 + Python 训练）

> 分工一句话：**C++ 承重，Python 增效**。界面、图像引擎、数据与血缘、流程编排、推理集成全部用 C++；训练、模型生产、评测脚本用 Python。两侧**进程隔离、协议通信、产物交接**（ONNX + 模型包），谁也不污染谁的依赖。

### 12.1 结论先行

| 层 | 语言 | 关键选型 | 为什么是它 |
|---|---|---|---|
| 桌面与画布 | C++ | Qt 6（Widgets + Quick/QRhi） | 原生性能、GPU 渲染、三平台一套代码 |
| 图像引擎 | C++ | OpenCV + libvips + OpenImageIO | 算子全 + 大图流式，内存可控 |
| 编排与数据 | C++ | Cpp-Taskflow + SQLite/PostgreSQL + CAS | DAG 与处理链同构；单机零部署 |
| 推理执行 | C++ | ONNX Runtime（CPU/CUDA/TensorRT/DirectML） | 模型以 ONNX 交付，运行时零 Python |
| 模型训练 | **Python** | PyTorch + Lightning / Ultralytics / MMEngine | 生态即战力，新模型当天可用 |
| 生成模型生产 | **Python** | diffusers + peft | 采样器、LoRA、ControlNet 生态在这边 |
| 训练服务 | **Python** | FastAPI / gRPC + pydantic + Hydra | 与 C++ 进程解耦，可跨机 |
| 插件边界 | C++ | 纯 C ABI 动态库 | 跨编译器 ABI 稳定 |

**一句话**：C++ 决定"能不能长期稳定地跑"，Python 决定"能不能跟上模型迭代"。两者用一条**进程边界**隔开，边界上是协议与文件，不是头文件。

### 12.2 职责边界（谁做什么，谁绝不做什么）

| 能力 | 归属 | 不该由谁做 | 交接物 |
|---|---|---|---|
| 界面、画布、交互、快捷键 | C++ | Python 不做 GUI | — |
| 像素算子（几何/色彩/滤波/复原） | C++ | Python 不参与实时处理 | 算子 schema（JSON） |
| 标注几何、命中测试、格式导出 | C++ | Python 不持有标注真值 | COCO/YOLO（导出时） |
| 资产、版本、血缘、权限 | C++ | Python 不写主库 | 数据集快照（只读导出） |
| 推理调度、阈值调参、结果可视化 | C++ | Python 不进推理热路径 | ONNX + model.json |
| 数据增强 | **两侧都要** | 不能各写一套语义 | 增强配置（JSON，两侧共用） |
| 模型训练、超参搜索、蒸馏 | Python | C++ 不做训练 | 权重 + ONNX + metrics.json |
| 评测指标计算 | **两侧都要** | 不能各定义一套口径 | 指标定义表 + metrics.json |
| 生成模型生产与微调 | Python | C++ 不做训练 | ONNX / TensorRT engine |
| 插件（算子/格式/模型） | C++ | — | C ABI 头文件 |

**两条硬规则**

1. **增强与指标必须"同源定义"**：增强用一份 JSON 描述（`{"op":"rotate","deg":15,...}`），C++ 用它做预览，Python 用它驱动 Albumentations；指标用一份 `metrics.json` 契约，两侧同名同义。否则"预览看到的"和"训练喂进去的"不是一回事，这是混合架构最容易出的隐蔽 bug。
2. **Python 不写主库**：训练服务只能读数据集快照、写自己的产物目录，元数据库由 C++ 侧统一写入。避免两侧并发写导致血缘断裂。

### 12.3 C++ 侧选型

| 组件 | 选型 | 版本基线 | 说明 |
|---|---|---|---|
| 语言 | C++20 | MSVC 2022 / Clang 17 / GCC 13 | concepts / ranges / `std::format` |
| 构建 | CMake + Ninja + vcpkg | 3.28+ | manifest 锁版本，三平台一致 |
| GUI | Qt 6 Widgets + Quick/QRhi | 6.8 LTS | LGPLv3 动态链接，商用可行 |
| 画布 | 自研 `QQuickItem` + 着色器 | — | 缩放/平移/分割对比/差异合成 |
| 图像 I/O | OpenImageIO / LibRaw / libheif / libavif / libjxl / libjpeg-turbo / libtiff / GDCM | — | 20+ 格式，含 RAW 与 DICOM |
| 处理 | OpenCV（core/imgproc/photo/calib3d/stitching） | 4.10 | 算子主力，Apache-2.0 |
| 超大图 | libvips | 8.16 | 流式、金字塔、内存恒定 |
| 数学 | Eigen / Ceres（标定） | 3.4 / 2.2 | 单应、光束法平差 |
| 色彩 | LittleCMS 2 / OpenColorIO（可选） | 2.16 / 2.3 | ICC 与 ACES |
| 推理 | ONNX Runtime | 1.20 | EP：CPU/CUDA/TensorRT/DirectML/CoreML |
| 并行 | oneTBB + Cpp-Taskflow | 2021.12 / 3.8 | 线程池 + DAG |
| 数据 | SQLite 3（WAL）+ SQLiteCpp / PostgreSQL（libpq） | 3.46 | 单机起步，团队升级 |
| 索引 | hnswlib | 0.8 | 百万级向量检索 |
| 序列化 | FlatBuffers + nlohmann/json | — | 二进制快、JSON 可读 |
| 网络 | cpp-httplib / Boost.Beast + ixwebsocket | — | `--server` 模式、与 Python worker 通信 |
| 日志/崩溃 | spdlog + fmt / Crashpad | — | 结构化日志、dump |
| 测试/分析 | GoogleTest + Benchmark / clang-tidy + ASan | — | CI 门禁 |

### 12.4 Python 侧选型（训练与模型生产）

| 用途 | 选型 | 说明 |
|---|---|---|
| 训练框架 | PyTorch 2.x + Lightning | 统一训练循环、AMP、DDP、断点续训 |
| 检测/分割 | Ultralytics（YOLO）/ MMDetection / MMSegmentation | 模板即战力；**注意 AGPL**（见 §12.11） |
| 分类/骨干 | timm | 上千预训练骨干 |
| 增强 | Albumentations | 与标注同步变换，语义严谨 |
| 生成 | diffusers + peft + accelerate | SD/SDXL/Flux、LoRA、ControlNet |
| OCR | PaddleOCR（训练侧） | 检测+识别，产物导 ONNX |
| 导出 | torch.onnx / onnxsim / onnxruntime 校验 | 导出即验证，避免"能训不能跑" |
| 服务 | FastAPI + gRPC（grpcio） | 流式日志与指标 |
| 配置 | pydantic + Hydra | 配置即契约，可校验、可组合 |
| 实验追踪 | TensorBoard（内置）/ MLflow（可选） | 不强制外部服务 |
| 环境 | uv + venv（锁 `requirements.lock`） | 秒级创建，版本可复现 |

**关键决定**：训练环境是**独立安装的可选组件**，不是主程序的依赖。没装它，软件照样能导入、处理、标注、推理、导出；装了它才多出"训练"页。降级必须明确提示，而不是报错。

### 12.5 两侧如何握手（三种耦合方式）

| 方式 | 做法 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| 嵌入解释器 | 进程内嵌 CPython / pybind11 | 无 IPC 开销 | GIL、崩溃连带、依赖冲突、打包地狱 | **仅用于小工具函数，绝不用于训练** |
| 本地服务 | Python worker 独立进程 + gRPC/HTTP | 崩溃隔离、可跨机、可复用、可独立升级 | 需要协议与进程管理 | **主路径** |
| 文件队列 | `job.json` 投递 → 产物目录 | 极简、离线可用、易调试 | 无实时性 | **兜底与 CI** |

**协议对象（四个就够）**

| 对象 | 字段要点 | 方向 |
|---|---|---|
| `Job` | job_id、type（train/eval/export）、dataset_snapshot、config、seed、resources | C++ → Python |
| `Event` | job_id、kind（log/metric/progress/artifact/error）、payload、ts | Python → C++（流式） |
| `Control` | job_id、action（cancel/pause/resume） | C++ → Python |
| `Artifact` | 类型（weights/onnx/metrics/report）、路径、sha256、元信息 | Python → C++ |

**生命周期**：C++ 启动 worker → 握手（版本、CUDA、GPU 列表、能力集）→ 提交 Job → 流式 Event 刷新曲线与日志 → Artifact 落盘并校验 → 复用或退出。
**幂等**：`job_id = hash(dataset_version + config + seed)`，重复提交直接复用产物。
**健壮性**：心跳 2s、超时 30s 判定失联；worker 崩溃只影响该任务，UI 提示"训练进程异常退出"并保留日志；僵尸进程随主程序退出清理。

### 12.6 模型交接与运行时对齐

- **交接格式**：ONNX（推理标准）+ `model.json`（输入尺寸、归一化、通道顺序、类别表、默认阈值、后处理参数）+ 可选 TensorRT engine（首次加载时编译缓存）。
- **一致性校验**：同一批 20 张图，Python 侧（PyTorch）与 C++ 侧（ORT）推理结果逐元素差 <1e-3 才允许入库，否则拒绝并标记"导出异常"。**这道闸门能拦掉 80% 的"训练好用、部署不对"**。
- **版本记录**：worker 上报 `torch / cuda / onnxruntime` 版本，写入模型血缘；C++ 侧记录 ORT 版本，二者不匹配时给出警告而非静默运行。
- **GPU 争用**：训练与推理默认分卡；单卡时训练任务降为低优先级并限制显存上限，避免把正在交互的推理挤爆。

### 12.7 为什么是混合，而不是单一语言

| 维度 | 全 C++ | 全 Python | **混合（本方案）** |
|---|---|---|---|
| 界面与交互性能 | 优 | 差（GIL、打包、渲染） | 优（Qt/QRhi） |
| 图像算子性能 | 优 | 中（numpy 拷贝多） | 优（OpenCV/libvips） |
| 模型生态 | 差（晚 3–6 个月） | 优 | 优（直接用 Python 生态） |
| 部署体积 | 小 | 大（解释器 + 依赖） | 中（训练组件可选安装） |
| 迭代速度 | 慢（重编译） | 快 | 训练侧快，框架侧稳 |
| 崩溃隔离 | 需自己做 | 天然（进程级） | 天然（两侧本就分进程） |
| 人力结构 | 全员 C++ | 全员 Python | 分工：系统组 + 算法组 |

结论：混合不是妥协，是**按变更频率切分**——界面与引擎变得慢、要求稳，用 C++；模型与训练变得快、要求生态，用 Python。边界只有一条，成本可控。

### 12.8 线程与进程模型

| 线程/进程 | 职责 | 约束 |
|---|---|---|
| UI 线程 | Qt 事件循环、面板、命令派发 | 绝不执行像素计算 |
| 渲染线程 | QRhi 提交、纹理上传、图层合成 | 只读 GPU 资源 |
| 计算池（oneTBB） | 算子、批量、增强预览 | 线程数 = 物理核 − 1，可取消 |
| 推理线程 | ORT session 执行 | 每 GPU 一个队列，批量合并 |
| IO 池 | 解码、写盘、CAS 哈希 | 异步、可 mmap |
| Python worker | 训练 / 评测 / 导出 | 独立进程、独立环境、独立显存配额 |

**内存三条规则**（不变）：`ImageBuffer` 引用计数 + 写时复制；大图 tile cache（默认 1.5 GB 预算）；GPU 纹理池化复用。

### 12.9 上线前必须打通的五项技术验证（各 2 周）

| # | 验证项 | 通过标准 | 失败预案 |
|---|---|---|---|
| 1 | QRhi 画布大图 | 4 亿像素 TIFF 缩放/平移 60fps，常驻内存 <1.5 GB | 分块 QImage + 区域重绘 |
| 2 | 处理链时延 | 1MP 代理，拖参数到画面 ≤120ms（3 算子链） | 常用算子改 GPU 着色器 |
| 3 | **C++ ↔ Python 联调** | 提交训练 → 流式曲线 → ONNX 回传 → C++ 加载推理，全链路 <5 分钟；kill worker 后 UI 不崩 | 退回文件队列模式 |
| 4 | ONNX 一致性 | 20 图逐元素差 <1e-3；INT8 量化后精度损失 <0.5% mAP | 固定 FP16，放弃量化 |
| 5 | 插件 ABI | 第三方 DLL 热加载、异常隔离、版本不匹配有明确报错 | 静态链接 + 重编译 |

### 12.12 交付与工程化

- **主安装包**：C++ 应用，安装包约 105–135 MB，安装后约 250–300 MB（含 ORT CPU 与轻量基础模型），安装即用，无需 Python；明细见 §12.13。
- **训练组件**：独立安装器（一键创建 uv 环境 + 拉取 CUDA 版 PyTorch），约 2–6 GB，**可选**。
- **降级策略**：未安装训练组件时，"训练"页显示安装引导，其余功能不受影响；已装但版本不兼容时给出明确提示与修复命令。
- **CI**：C++ 三平台矩阵 + Python 单测/训练冒烟（1 epoch 小数据集）；协议层做双向兼容测试（旧 worker ↔ 新客户端）。
- **版本矩阵**：主程序 ↔ worker 协议版本语义化（`MAJOR.MINOR`），MAJOR 不匹配拒绝连接，MINOR 允许并提示。

### 12.13 体积预算与压缩策略

> 先给结论：**软件本体不是体积问题，用户数据才是。** 主程序装完约 250–300 MB，训练组件 1.2–5.5 GB（可选），而 1 万张 1200 万像素的照片就有 40 GB 上下。所以体积设计要分两套：一套管"装什么"，一套管"存什么"。

#### 12.13.1 主程序占用（Release x64，不含调试符号）

| 组件 | 未压缩 | 说明 |
|---|---|---|
| Qt 6 运行库 + QML 模块 + 插件 | 50–60 MB | 只带 Widgets/Quick/Network/Svg/图像插件，不含 WebEngine、3D、Charts |
| OpenCV（裁剪编译） | 22–55 MB | 只留 core/imgproc/photo/calib3d/stitching/features2d；关 dnn 与 IPP 后约 22 MB，全量 world 约 55–65 MB |
| libvips + glib 依赖 | 20–25 MB | 大图流式与金字塔的核心 |
| OpenImageIO + 格式插件 | 20–25 MB | TIFF/EXR/PNG/JPEG 统一读写 |
| 图像编解码库（jpeg-turbo/png/tiff/webp/avif/jxl/heif） | 20–28 MB | libjxl 与 libaom 占大头 |
| FFmpeg（LGPL 共享库） | 30–38 MB | 视频抽帧与序列处理 |
| ONNX Runtime（CPU） | 12–16 MB | CUDA/TensorRT EP 另计 |
| GDCM / LibRaw / LittleCMS / Ceres | 12–15 MB | DICOM / RAW / ICC / 标定 |
| 自研可执行 + 插件 + 资源（图标/着色器/翻译） | 25–35 MB | 含 shader、QSS、i18n |
| **合计（安装后）** | **约 250–300 MB** | |
| **安装包（LZMA2 压缩）** | **约 105–135 MB** | 压缩比 2.3–2.6× |
| 可选：CUDA EP + TensorRT provider | +120–200 MB | 需要 GPU 推理时勾选 |
| 可选：CUDA 运行库（cudart/cuBLAS/cuDNN） | +600 MB–1.5 GB | 通常依赖用户驱动与系统 CUDA，不随包分发 |

#### 12.13.2 可选组件

| 组件 | 体积 | 交付方式 |
|---|---|---|
| 训练组件（CPU 版 PyTorch） | 约 1.1–1.4 GB | 独立安装器 |
| 训练组件（CUDA 版 PyTorch + MMCV + diffusers） | 约 3.5–5.5 GB | 独立安装器，按显卡勾选 |
| 基础模型包（YOLO-n/s、OCR、MobileSAM） | 80–150 MB | 随主包 |
| SAM / SAM2（ViT-B，FP32 / FP16） | 375 / 190 MB | 按需下载 |

| 完整生成套件（SDXL + ControlNet ×4 + LoRA） | 8–15 GB | 按需下载 |

#### 12.13.3 用户数据占用（真正的成本中心）

| 数据类型 | 估算 | 说明 |
|---|---|---|
| 原图 | **1 万张 12MP JPEG ≈ 40 GB** | 不可压缩，且是唯一必须保留的 |
| 金字塔瓦片 | 原图体积的 25–35% | 4 层金字塔理论 1.33×，用 WebP 有损后约 1.3×；**可按需重建，属可回收空间** |
| 缩略图与预览 | 原图体积的 1–3% | 长边 256/1024 两档 |
| 处理产物（派生资产） | 原图的 30–80% | 由 Recipe 可重算，**默认只保留最近 N 个版本** |
| 向量索引 | 每 100 万图约 2–3 GB | 512 维 FP32 + HNSW 图结构；改 INT8 可降到 0.6 GB |
| 元数据库（SQLite） | 每 100 万资产 2–4 GB | 含标注、血缘、审计 |
| 日志与缓存 | 上限可配，默认 2 GB | 滚动清理 |

**关键判断**：索引、瓦片、派生资产、缓存**全部可重建**，必须支持"一键回收"并显示占用；只有原图与标注是不可再生的。

#### 12.13.4 能压到什么程度（按手段拆）

| 手段 | 典型收益 | 代价与风险 | 建议 |
|---|---|---|---|
| 编译期裁剪（LTCG / `-ffunction-sections` / `/OPT:ICF` / strip） | 10–20% | 无 | **必做** |
| 自编译 OpenCV 裁剪模块 | 该库 60% | 需维护编译脚本 | **必做** |
| Qt 模块裁剪 + 去未用语言包 | 20–30% | 需检查依赖 | **必做** |
| 安装包 LZMA2 / 7z | 2.3–2.6× | 解压稍慢 | **必做** |
| 模型 FP16 | 50% | 精度损失可忽略 | **默认** |
| 模型 INT8 量化 | 75% | 需校准，精度损失 0.3–1% | 可选档 |
| 模型 4-bit（GPTQ/AWQ 类） | 85–90% | 需专用推理核，质量有损 | 仅生成大模型 |
| 按需下载（模型/生成模块分离） | 主包 −70% | 首次使用需联网 | **必做** |
| 差分更新（bsdiff/zstd patch） | 单次更新 5–20 MB | 需维护版本基线 | **必做** |
| 缩略图/瓦片用 WebP 或 JXL | 50–65% | 解码稍慢 | 必做 |
| 冷数据 zstd 归档 | 30–40% | 访问需解压 | 归档盘可选 |
| 可执行文件 UPX | 30–50% | **杀软误报、启动变慢、签名易失效** | **不推荐**主程序，仅 CLI |

**不建议的两条**

1. **UPX 压主程序**：省几十 MB，换来杀毒软件误报与冷启动变慢，得不偿失。
2. **静态链接 Qt 以求"单文件"**：体积未必更小，且 LGPL 下静态链接会触发"必须提供可重链接目标文件"的义务，法务成本高于收益。

#### 12.13.5 体积目标（写进验收）

| 指标 | 目标 | 说明 |
|---|---|---|
| 主安装包 | ≤ 135 MB | 不含 CUDA EP |
| 安装后占用 | ≤ 300 MB | 含基础模型 |
| 冷启动 | ≤ 1.5 s | 机械硬盘 ≤ 3 s |
| 安装包增量更新 | ≤ 20 MB/次 | 差分更新 |
| 缓存与可回收空间 | 界面上可见、可一键清理 | 显示"可释放 N GB" |
| 数据目录 | 用户可指定，支持外置盘/网络盘 | 原图与缓存可分盘 |

### 12.14 运行内存与显存预算

> 先把三种"占用"分清，它们常被混为一谈：**磁盘**是装完占多大（见 §12.13，250–300 MB）；**内存**是跑起来吃多少 RAM；**显存**是 GPU 上吃多少 VRAM。训练组件是独立进程，它的内存要单独算。

#### 12.14.1 常驻内存（空载与基础加载）

| 状态 | 内存增量 | 说明 |
|---|---|---|
| 冷启动完成、未打开图 | 180–260 MB | Qt + 基础库 + 空的任务中心 |
| 打开一张 12MP 图 | +60–120 MB | 原图 36 MB + 代理 + 直方图缓存 |
| 加载 1 个检测模型（ORT CPU） | +150–300 MB | 含权重与推理 arena |
| 启用 CUDA EP | +300–600 MB | CUDA context 是固定开销，与模型大小无关 |
| 百万级向量索引常驻 | +0.6–3 GB | 512 维 FP32 + HNSW 图；INT8 或 mmap 可降至 0.6–1 GB |
| 训练组件（Python worker） | +3–6 GB | 仅训练时存在，与主程序隔离 |

#### 12.14.2 工作内存（按图算，而不是拍脑袋）

**估算公式**：`峰值 ≈ W × H × 通道 × 位深/8 × 副本数 + 代理图 + 瓦片缓存`

| 图像规模 | 单副本 | 典型峰值（原图+结果+差异+撤销） | 策略 |
|---|---|---|---|
| 12 MP（4000×3000, RGB8） | 36 MB | 250–400 MB | 直接整幅处理 |
| 100 MP | 300 MB | 1.2–1.6 GB | 建议启用瓦片 |
| 4 亿像素（20000×20000） | 1.2 GB | 禁止整幅 | **只走瓦片 + LRU 缓存（默认 1.5 GB 上限）** |
| 16 bit 多波段（10 波段） | 单副本 ×10 | 按波段分块 | 按需解码 + 波段流式 |

**并发与批处理**

- 单图峰值目标 ≤1.5 GB；超过自动切瓦片并提示。
- 批处理并发按可用内存动态下调：8 线程 × 12 MP × 2 缓冲 ≈ 580 MB；上限建议 2 GB，超限降并发而不是 OOM。
- 大图批处理必须**串行 + 瓦片**，否则 N × 1.2 GB 直接击穿。

#### 12.14.3 显存预算

| 任务 | 显存 | 备注 |
|---|---|---|
| 检测推理 640²（YOLO-s） | 1.5–3 GB | 含 CUDA context |
| 分割推理 1024² | 3–5 GB | 滑窗时按切片累积 |
| SAM 图像编码 1024² | 2.5–4 GB | 编码结果需缓存，支持多次点击复用 |
| OCR 检测+识别 | 1–2 GB | 两段可分开加载 |
| SD-Turbo 1024² 生成 | 6–8 GB | FP16 |
| SDXL 1024² 生成 | 10–12 GB | 可开 VAE tiling 降峰 |
| 检测训练 640² bs16（AMP） | 8–12 GB | 梯度累积可降 batch 换等效 |
| 分割训练 1024² bs8 | 12–20 GB | 混合精度必开 |
| 生成模型 LoRA 微调 1024² | 12–24 GB | 梯度检查点可再降 30% |

#### 12.14.4 推荐硬件配置

| 使用场景 | 内存 | 显存 | 说明 |
|---|---|---|---|
| 只看图、调图、导出 | 8 GB（推荐 16 GB） | 不需要 | 纯 CPU 可用 |
| + 标注 + 小模型推理 | 16 GB | 4–6 GB | 入门卡即可 |
| + 训练检测模型 | 32 GB | 8–12 GB | RTX 3060/4060 级 |
| + 训练分割 / 生成 | 32–64 GB | 16–24 GB | RTX 4080/4090 级 |
| 团队服务端（并发 5–10） | 64 GB+ | 24 GB+ | 推理与训练分卡 |

#### 12.14.5 内存保护规则（写进验收）

1. **加载前预判**：估算所需内存，超过可用量 70% 时降级（瓦片/降采样）并提示，不做"加载到一半崩掉"。
2. **训练前预检**：可用内存 < 预估 × 1.3 或显存 < 预估 × 1.2 时拒绝启动，给出"降 batch / 开 AMP / 关后台"三条建议。
3. **同机训练时预留 4 GB** 给系统与 UI，避免训练把交互挤死。
4. **可观测**：状态栏常驻显示当前进程内存与显存占用，超过阈值变黄/变红。
5. **可回收**：切图、关闭项目、结束任务后立即释放大缓冲；缓存可一键清空。

| 项 | 体积 | 说明 |
|---|---|---|
| **纯文本源码**（C++/Python/CMake/QSS/QML） | **10–14 MB** | 按 40 字节/行估算，十几万行也就十几 MB |

**开发机那 8–15 GB 花在哪**

| 内容 | 体积 |
|---|---|
| vcpkg 依赖（编译好的 OpenCV/Qt/ORT/FFmpeg…） | 1.5–3 GB |
| build 目录（Debug + Release，含 PDB） | 3–8 GB |
| ccache / sccache | 1–5 GB |
| Qt SDK（若随工程管理） | 2–3 GB |

#### 12.15.3 四条仓库纪律（否则半年后必爆）

1. **二进制不进主仓**：模型（`.onnx`）、演示视频、金标大图一律走 Git LFS 或制品库（S3/MinIO），仓库只存指针。
2. **构建产物与依赖零入库**：`build/`、`vcpkg_installed/`、`__pycache__`、`logs/` 全在 `.gitignore`；vcpkg 用 manifest 模式，锁版本不锁文件。
3. **`.gitattributes` 管住换行与二进制**：`*.png binary`、`*.onnx filter=lfs`、`* text=auto eol=lf`，避免 Windows/macOS 互相污染。
4. **按 target 拆分构建**：`ft_core/ft_ops` 可独立编译与测试，改 UI 不重编算子，把增量构建压到 1 分钟内。

#### 12.15.4 一句话结论

**源码 50–80 MB、代码 18–25 万行；开发机完整目录 8–15 GB，其中 95% 是依赖与构建产物，不是你的代码。** 真正需要长期经营的是"仓库纪律"，不是磁盘容量。

## 13. 性能与工程约束

| 场景 | 目标 | 手段 |
|---|---|---|
| 打开 4 亿像素图 | <2s 可交互 | 预生成金字塔瓦片、按需解码、区域重绘 |
| 参数调整预览 | <150ms（1MP 代理） | 降采样代理 + 结果缓存 + debounce |
| 批处理 10 万张（简单算子） | >30 张/秒（多核） | 进程池、流式读写、零拷贝、跳过未变更 |
| 标注绘制 | 60fps | 分层 Canvas（底图/标注/交互层分离）、脏矩形重绘 |
| 百万级检索 | P95 <150ms | HNSW + 量化、索引与主库分离 |
| 模型首帧 | <3s | 模型常驻、预热一次前向、算子融合 |
| 训练启动 | <60s | 环境预检、数据索引预构建、避免每次扫盘 |

**工程红线**

- **内存上限**：任何路径不得一次性读入全图（除用户显式要求）；大图必须走 tiling。
- **取消语义**：所有长任务可取消，取消后资源必须释放（GPU 上下文尤其）。
- **幂等**：同一 Run 重跑覆盖同一产物，不产生垃圾。
- **缓存键**：`hash(输入) + 算子版本 + 规范化参数 + seed`，缺一不可。
- **失败可诊断**：错误必须带"哪张图、哪个算子、哪个参数、原始异常"，而不是"处理失败"。

## 16. 与开源生态的映射及差异化

| 能力域 | 直接复用 | 自研部分 | 差异化 |
|---|---|---|---|
| 像素算子 | OpenCV / libvips | C++ 算子库 + schema 注册表、代理预览、批处理引擎 | 参数物理化 + 可复现 Recipe |
| 增强 | OpenCV 仿射/色彩算子（对齐 Albumentations 语义） | 与标注 schema 绑定的可视化配置 | 变换后即时校验对齐 |
| 标注 | 参考 CVAT 交互、X-AnyLabeling 的 AI 辅助 | QRhi 覆盖层 + 统一几何模型 + 布尔运算 + 复核流 | 标注结果直接进训练，无格式往返 |
| 提示分割 | SAM / SAM2 导出 ONNX | ORT 会话常驻、编码结果缓存、掩码后处理 | 点击级延迟 |
| 训练 | PyTorch / Ultralytics / MMEngine + Lightning（Python worker） | 数据集绑定、任务编排、实验对比、ONNX 交接 | "选数据集→选模板→训练"三步，界面无 Python |
| 评测 | 参考 FiftyOne 的分析视图 | 自研 QPainter 图表 + 守门集/回归对比/切片指标 | 上线前自动拦截退化 |
| 生成 | ONNX/TensorRT 导出的扩散模型、stable-diffusion.cpp | 节点编排 + 与标注掩码/检测框互通 | 生成受控于已有标注，而非凭空 |
| 压缩导出 | libjpeg-turbo / libwebp / libavif / libjxl | 率失真搜索、体积约束求解 | 按"目标体积"反解参数 |
| 检索 | hnswlib / CLIP(ONNX) | 血缘图 + 泄漏检测 | 数据集健康度而非单纯相似 |
| 数据版本 | 参考 DVC 思想 | 内置快照与 diff | 无需 Git 也能用 |

**四条护城河**

1. **单一数据模型**：六个环节共享 Asset/Annotation/DatasetVersion，不存在"导出→再导入"。
2. **可复现**：任何产物可回溯到 `输入 + 配方 + 参数 + 种子 + 环境`，这是科研与工业的共同刚需。
3. **专业正确性**：色彩管理、位深、坐标约定、值域契约做到"不静默出错"，这是与轻量工具的分水岭。
4. **本地优先**：数据不出机器也能全功能运转，切中涉密与隐私场景。

## 18. 风险与取舍备忘

1. **范围风险**：12 个模块对一个团队过重。建议按 §15 分期，P0–P2 即构成可售的最小闭环（看图改图 + 标注 + 训练），P3–P5 是护城河不是入场券。
2. **性能风险**：大图与批处理是最容易翻车处，libvips + 金字塔要在 P0 就落地，不能后补。
3. **生态风险**：模型与格式演进快，注册表 + 插件必须第一天就有，否则两年后无法跟进新模型。
4. **合规风险**：生成与复原的"推断内容"标识要在产品层默认开启，不能等出事再补。
5. **可视化滞后风险**：最常见的翻车不是算不出来，而是"算完了看不见"。对比引擎必须在 P0 就成形，不能等算子做完再补 UI；否则每加一个算子都要返工一次交互。
6. **混合架构的边界风险**：C++ 与 Python 最容易在"增强语义"和"指标口径"上分叉（预览一套、训练一套）。必须执行 §12.2 的两条硬规则：增强配置与指标定义单一来源、Python 不写主库。另一条红线是**禁止把训练依赖塞进主安装包**——一旦装了，主程序就会被 CUDA/PyTorch 版本绑死。
7. **双语言协作风险**：C++ 与 Python 两套人、两套工具链，接口一变就要双方对齐，容易互相等。缓解：协议先行（`job.proto` 定完再各自实现）、契约测试进 CI、每周一次联调；训练模板做成 Python 侧可独立开发的插件，减少对 C++ 侧的依赖。
8. **取舍声明**：本方案不做通用视频编辑、不做 3D 重建、不做通用标注众包平台——聚焦静态图像的"数据—模型"闭环。
